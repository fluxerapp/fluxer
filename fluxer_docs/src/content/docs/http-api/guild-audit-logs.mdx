An audit log entry records one change to a guild and who made it. You get entries with [List guild audit logs](#list-guild-audit-logs) or its [Admin API counterpart](/admin-api/guilds/#list-guild-audit-logs). Entries are kept for 45 days.

Each new entry is also sent as [Guild Audit Log Entry Create](/gateway/events/#guild-audit-log-entry-create) to sessions with `VIEW_AUDIT_LOG`.

## Audit log reason

A route marked Audit reason accepts the `X-Audit-Log-Reason` header, listed with the [standard request headers](/http-api/#standard-request-headers). The value is trimmed and used as sent, with no percent-decoding. A blank value or one over 512 characters is dropped and the request still succeeds.

When the header is absent, [Create or replace guild ban](/http-api/guild-moderation/#create-or-replace-guild-ban) uses the body `reason`, and [Modify guild member](/http-api/guild-members/#modify-guild-member) uses `timeout_reason` if the body sets `communication_disabled_until`. Bot additions, message deletions made by [Delete message attachment](/http-api/messages/#delete-message-attachment) and entries made by [message deletion consolidation](#list-guild-audit-logs) never have a reason.

## Guild audit log response object

One page of entries with the users, webhooks and threads they reference.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| audit_log_entries | array[[guild audit log entry](#guild-audit-log-entry-object) object] | The page of entries |
| users | array[[partial user](/http-api/users/#partial-user-object) object] | The users the entries reference |
| webhooks | array[[audit log webhook](#audit-log-webhook-object) object] | The webhooks that webhook entries target and that still exist |
| threads?<sup>1</sup> | array[[thread](/http-api/threads/#thread-object) object] | The threads that thread entries target and that still exist |

<sup>1</sup> Present only for a bot and for a user session that declares the [`channel_threads` client capability](/http-api/threads/#client-capability)

`users` has every user an entry was made by or refers to. A deleted user is returned as `DeletedUser`.

## Guild audit log entry object

One change to the guild.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| id | snowflake | The ID of the entry |
| action_type | integer | The [audit action](#audit-actions) |
| user_id<sup>1</sup> | snowflake | The ID of the user that did the action |
| target_id<sup>2</sup> | ?string | The ID of the affected entity |
| reason? | string | The [audit log reason](#audit-log-reason) |
| options? | [audit log options](#audit-log-options-object) object | The options the action records |
| changes? | array[[audit log change](#audit-log-change-object) object] | The fields the action changed |

<sup>1</sup> `0`, the system user, when Fluxer made the change itself. That covers a member removal, ban or unban by an instance admin through the [Admin API](/admin-api/), an automatic invite pause and a managed role update

<sup>2</sup> The invite code for [INVITE_CREATE](#audit-actions) and [INVITE_DELETE](#audit-actions), and null for [MESSAGE_BULK_DELETE](#audit-actions)

### Example

```json
{
  "id": "1501314428688998184",
  "action_type": 24,
  "user_id": "1489002177550843905",
  "target_id": "1489002177550843906",
  "reason": "Nickname violated the rules",
  "changes": [{"key": "nick", "old_value": "spam bot", "new_value": null}]
}
```

## Audit actions

Each value is an `action_type`, and the `action_type` query filter takes the same values. An update or a member move records an entry only when something changed. For GUILD_UPDATE, a change to only `guild_id`, `member_count` or an image width or height records nothing.

| Value | Name | Description |
| --- | --- | --- |
| 1 | GUILD_UPDATE | Guild settings, custom invite URL or ownership changed. `target_id` is the guild |
| 10 | CHANNEL_CREATE | Channel created. `target_id` is the channel and the option is `type` |
| 11 | CHANNEL_UPDATE | Channel changed. `target_id` is the channel and the option is `type` |
| 12 | CHANNEL_DELETE | Channel deleted. `target_id` is the channel and the option is `type` |
| 13 | CHANNEL_OVERWRITE_CREATE<sup>1</sup> | Permission overwrite created. `target_id` is the role or member |
| 14 | CHANNEL_OVERWRITE_UPDATE<sup>1</sup> | Permission overwrite changed. `target_id` is the role or member |
| 15 | CHANNEL_OVERWRITE_DELETE<sup>1</sup> | Permission overwrite deleted. `target_id` is the role or member |
| 20 | MEMBER_KICK | Member removed by a moderator. `target_id` is the user |
| 21 | MEMBER_PRUNE<sup>2</sup> | Inactive members pruned |
| 22 | MEMBER_BAN_ADD | Ban created or replaced. `target_id` is the user and the option is `delete_message_seconds` |
| 23 | MEMBER_BAN_REMOVE | Ban removed. `target_id` is the user |
| 24 | MEMBER_UPDATE | Member changed. `target_id` is the user |
| 25 | MEMBER_ROLE_UPDATE | One role added to or removed from a member. `target_id` is the user and the option is `role_name` |
| 26 | MEMBER_MOVE<sup>3</sup> | Member moved to another voice channel. `target_id` is the user |
| 27 | MEMBER_DISCONNECT<sup>3</sup> | Member disconnected from voice. `target_id` is the user |
| 28 | BOT_ADD | Bot added. `target_id` is the user and the option is `temporary` |
| 30 | ROLE_CREATE | Role created. `target_id` is the role |
| 31 | ROLE_UPDATE | Role changed. `target_id` is the role and the option is `role_name` |
| 32 | ROLE_DELETE | Role deleted. `target_id` is the role |
| 40 | INVITE_CREATE<sup>4</sup> | Invite created. `target_id` is the invite code |
| 41 | INVITE_UPDATE<sup>2</sup> | Invite changed. `target_id` is the invite code |
| 42 | INVITE_DELETE<sup>4</sup> | Invite deleted. `target_id` is the invite code |
| 50 | WEBHOOK_CREATE<sup>5</sup> | Webhook created. `target_id` is the webhook and the options are `channel_id` and `type` |
| 51 | WEBHOOK_UPDATE | Webhook changed. `target_id` is the webhook and the options are `channel_id` and `type` |
| 52 | WEBHOOK_DELETE<sup>5</sup> | Webhook deleted. `target_id` is the webhook and the options are `channel_id` and `type` |
| 60 | EMOJI_CREATE | Emoji created. `target_id` is the emoji |
| 61 | EMOJI_UPDATE | Emoji changed. `target_id` is the emoji |
| 62 | EMOJI_DELETE | Emoji deleted. `target_id` is the emoji |
| 72 | MESSAGE_DELETE | Message deleted. `target_id` is the message and the option is `channel_id` |
| 73 | MESSAGE_BULK_DELETE | Messages deleted together. `target_id` is null and the options are `channel_id` and `count` |
| 74 | MESSAGE_PIN | Message pinned. `target_id` is the message and the options are `channel_id` and `message_id` |
| 75 | MESSAGE_UNPIN | Message unpinned. `target_id` is the message and the options are `channel_id` and `message_id` |
| 90 | STICKER_CREATE | Sticker created. `target_id` is the sticker |
| 91 | STICKER_UPDATE | Sticker changed. `target_id` is the sticker |
| 92 | STICKER_DELETE | Sticker deleted. `target_id` is the sticker |
| 110 | THREAD_CREATE | Thread created. `target_id` is the thread |
| 111 | THREAD_UPDATE | Thread changed. `target_id` is the thread and the option is `type` |
| 112 | THREAD_DELETE | Thread deleted. `target_id` is the thread and the option is `type` |

<sup>1</sup> The options are `id`, `type`, `channel_id` and `role_name`, and `role_name` is recorded only for a role other than `@everyone`

<sup>2</sup> Never recorded. The filter still accepts it

<sup>3</sup> The options are `channel_id` and `count`, and `count` is always `1`. `channel_id` is the new channel for a move and the channel the member left for a disconnect

<sup>4</sup> The options are `max_age`, `max_uses`, `temporary`, `channel_id` and `inviter_id`, and the last two are recorded only when the invite has them

<sup>5</sup> [Follow announcement channel](/http-api/channels/#follow-announcement-channel) records these in the guild that follows the channel, with `type` `2`

Deleting a channel deletes its threads and records only CHANNEL_DELETE.

## Audit log options object

An action records only the options listed for it in [audit actions](#audit-actions), and `options` is omitted when it has none.

| --- | --- | --- |

| count | number | The number of entities the action affected |
| delete_member_days<sup>1</sup> | string | The whole days of messages a ban deleted |
| delete_message_seconds | number | The seconds of messages a ban deleted, present when positive |
| id | string | The ID of the role or member an overwrite applies to |
| integration_type<sup>2</sup> | number | The type of the integration |
| inviter_id | string | The ID of the user that created the invite |
| max_age | number | The invite lifetime in seconds |

<sup>1</sup> Present only on older ban entries, which have no `delete_message_seconds`

<sup>2</sup> Never recorded

## Audit log change object

One field an action changed. A creation has only `new_value`, a deletion has only `old_value`, and a modification has both.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| key | string | The name of the field that changed, from the [change fields](#change-fields) of the target |
| old_value? | audit log change value | The value before the change |
| new_value? | audit log change value | The value after the change |

A change value is a string, number, boolean, null, an array of strings or numbers, or an object with `added` and `removed` string arrays. Permission masks and snowflakes are decimal strings. An update lists only the fields that differ.

## List guild audit logs

<RouteHeader method="GET" path="/v1/guilds/{guild_id}/audit-logs" bot />

Returns one page of audit history as a [guild audit log response](#guild-audit-log-response-object) object, newest first. You need `VIEW_AUDIT_LOG`.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| limit? | integer | The maximum number of entries to return (0-100, default 50) |
| before? | snowflake | Returns entries older than this entry ID |
| after? | snowflake | Returns entries newer than this entry ID |
| user_id? | snowflake | Returns only entries made by this user |
| action_type? | integer | Returns only entries with this [audit action](#audit-actions) |

Two or more [MESSAGE_DELETE](#audit-actions) entries in a row by the same user in the same channel are replaced by one [MESSAGE_BULK_DELETE](#audit-actions) entry with a new ID and a `count`. This happens within about a minute of the deletions, and again on any read without `user_id` or `action_type`.

A user session without the [`channel_threads` capability](/http-api/threads/#client-capability) gets no entries about threads, forum channels or media channels, and filtering by actions 110 to 112 returns 400.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [guild audit log response](#guild-audit-log-response-object) object | The page was returned |
| 400 | [error response](/http-api/#error-response) | `CANNOT_SPECIFY_BOTH_BEFORE_AND_AFTER` when both cursors are sent, or a filter value is invalid |
| 403 | [error response](/http-api/#error-response) | You lack `VIEW_AUDIT_LOG` |
| 404 | [error response](/http-api/#error-response) | The guild does not exist |

The rate limit is 20 requests per 10 seconds, on the `guild:audit_logs::guild_id` bucket.
