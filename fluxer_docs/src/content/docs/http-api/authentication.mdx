These routes create accounts, sign people in and manage their sessions. Every route is under `/v1/auth`, and [Authentication](/authentication/) explains the token formats.

## Shared behavior

Most routes here need no `Authorization` header, because the request has its own ticket, code or credential. The routes that need a user session token, except [log out](#log-out), reject a bot token and an OAuth2 bearer token with 403 `ACCESS_DENIED`.

An instance reports how people sign in as `account_identity` in its [instance features](/http-api/instance/#instance-features-object). On a `username` instance, these routes return 400 `EMAIL_UNAVAILABLE_ON_INSTANCE` and send no email.

- [Verify an email address](#verify-an-email-address)
- [Resend email verification](#resend-email-verification)
- [Request password recovery](#request-password-recovery)
- [Revert an email change](#revert-an-email-change)
- [Authorize an IP address](#authorize-an-ip-address)
- [Resend IP authorization](#resend-ip-authorization)

When the instance enforces SSO, the password, passkey, email code, registration, email verification, password reset, recovery, IP authorization and username routes return 403 `SSO_REQUIRED`. The SSO routes, logout, the session routes, [redeem a sign-in link](#redeem-a-sign-in-link), the desktop and origin handoff routes and the MFA routes for a ticket from [complete SSO](#complete-sso) keep working.

Each sign-in creates one session, and a session lasts until it is revoked. When a session is revoked, its Gateway connection gets [Invalid Session](/gateway/overview/#invalid-session) with `d: false`.

## Authentication token response object

A new session token and the account it belongs to. Every route that signs someone in returns these fields.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| token | string | The new user session token, returned only here |
| user_id | snowflake | The authenticated user ID |
| user | [partial user](/http-api/users/#partial-user-object) object | The authenticated account |
| device_proof? | string | A value to send to [identify an account](#identify-an-account) from this device later |
| entry?<sup>1</sup> | ?[guild entry](/http-api/users/current-user/#guild-entry-object) object | The community to open next, from the invite used at sign-up |

<sup>1</sup> Returned only by registration, and null when no invite applied or the account still has to enter a date of birth

When a route can return this object or a different one, check for `token`.

## Network block response

A request from a blocked network returns 403 `GLOBAL_IP_BANNED` or `GLOBAL_IP_TEMPORARILY_BANNED`, and the [error response](/http-api/#error-response) has these extra fields.

| Field | Description |
| --- | --- |
| `ip_address` | The client IP address |
| `appeal_email` | Always `null` on a self-hosted instance |
| `appeals_supported` | Always `false` on a self-hosted instance |
| `ban_kind` | `permanent`, or `temporary_24h` for any ban with an expiry |
| `expires_at` | When the ban ends as an ISO 8601 timestamp, or `null` |
| `reason` | The rule behind the block as `title` and `url`, or `null` |
| `product_name` | The instance name used in `message` |

A blocked network can still load `GET /.well-known/fluxer`, which the app uses to show the block message. Password, passkey, MFA and SSO sign-in still answer from a blocked network so a suspended or closed account sees its [enforcement notice](#enforcement-notice-object). Every other result is the same network block error.

## Enforcement notice object

`ACCOUNT_SUSPENDED_TEMPORARILY` and `ACCOUNT_SUSPENDED_PERMANENTLY` errors have a `notice` field with the enforcement notice for the account, in the request locale.

| Field | Description |
| --- | --- |
| `decision_id` | The decision reference, or `null` |
| `kind` | `suspension` or `closure` |
| `permanent` | `true` for a suspension with no end date |
| `issued_at` | When the decision was made, or `null` |
| `ends_at` | When the suspension ends, or `null` |
| `deletion_at` | When the account will be deleted, or `null` |
| `summary` | One sentence saying what happened |
| `effects` | What the decision means for the account |
| `rule` | The rule broken as `title` and `url`, or `null` |
| `facts` | The finding, then where and when it happened |
| `statement` | A note from the team, or `null` |
| `how_we_decided` | How the case came to the team and who decided |
| `appeal` | `email`, `deadline` and `account_has_email`, or `null` |
| `redress` | Other ways to challenge the decision |

Lines in `effects`, `facts` and `redress` can have Markdown links, `[text](url)`, which the app shows as links.

## MFA challenge response object

Sign-in routes return this object when the account has a second factor. Finish with [complete login with TOTP](#complete-login-with-totp) or [complete login with WebAuthn MFA](#complete-login-with-webauthn-mfa).

### Structure

| Field | Type | Description |
| --- | --- | --- |
| mfa | boolean | Always `true` |
| ticket | string | The ticket for the MFA route, valid for 5 minutes or until 5 wrong codes |
| allowed_methods | array[string] | The methods the account can use, from `totp`, `webauthn` and `backup_codes` (max 10 items) |
| totp | boolean | Whether the account has an authenticator app |
| webauthn | boolean | Whether passkeys are turned on as a second factor |
| backup_codes | boolean | Whether the account has an unused backup code |

Backup codes go to [complete login with TOTP](#complete-login-with-totp) as `code`.

## Complete SSO

<RouteHeader method="POST" path="/v1/auth/sso/complete" unauthenticated />

Signs in or creates the account linked to the provider identity and returns an [SSO completion response](#sso-completion-response-object). The state works once, and after any failure you start again with [start SSO](#start-sso).

An unlinked identity is linked to the account with the same verified email, after the second factor if the account has one. A new account has no password and accepts no invite, and it joins the instance's single community when the instance has one. On an `email` instance it gets the provider's verified email, and when SSO is enforced each sign-in sets the account email to it.

:::caution[A verified provider email takes over a matching account]
Turn on SSO only for a provider that controls the email addresses it asserts.
:::

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| code | string | The authorization code from the provider (1-4096 characters) |
| state | string | The state from [start SSO](#start-sso) (1-4096 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [SSO completion response](#sso-completion-response-object) | The account was signed in, or its second factor is needed |
| 400 | [error response](/http-api/#error-response) | `INVALID_OR_EXPIRED_SSO_STATE`, `SSO_EMAIL_NOT_VERIFIED` or another provider or linking code |
| 403 | [error response](/http-api/#error-response) | `SSO_REQUIRED` when the account is unknown and new accounts are off |
| 403 | [error response](/http-api/#error-response) | `REGISTRATION_PENDING_APPROVAL`, `REGISTRATION_REJECTED` or a suspension code |

The rate limit is 15 requests per 10 seconds, on the `auth:sso:complete` bucket.

## Register an account

<RouteHeader method="POST" path="/v1/auth/register" unauthenticated />

Creates an account and returns an [authentication token response](#authentication-token-response), or a [registration pending approval response](#registration-pending-approval-response-object) when an admin has to approve it. The request needs a [CAPTCHA](/topics/captcha/), and joining a community sends [Guild Member Add](/gateway/events/#guild-member-add).

A body with only `global_name` creates an [instant account](/admin-api/instance/#auth-configuration-object) with a username made from that name. The person keeps it by [claiming it](/http-api/users/current-user/#claim-an-account).

If you lose the response, try to sign in before you retry, because registration isn't idempotent.

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| X-Captcha-Token? | string | The solved ALTCHA challenge, see [CAPTCHA handling](/topics/captcha/) |
| Accept-Language? | string | The language for the account and the verification email |

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| email?<sup>1</sup> | string | The account email address |
| username?<sup>2</sup> | string | The username (1-32 characters, letters, digits and underscores) |
| global_name? | string | The display name (1-32 characters) |
| password?<sup>3</sup> | string | The password (8-256 characters) |
| date_of_birth?<sup>4</sup> | string | The date of birth as `YYYY-MM-DD` |
| consent?<sup>5</sup> | boolean | Whether the person accepted the terms of service (default false) |
| invite_code? | ?string | An invite to accept after registration (0-256 characters) |
| registration_url_code?<sup>6</sup> | ?string | A registration URL code from an admin (1-128 characters) |
| theme? | string | The starting theme, one of `dark`, `dark_legacy`, `coal`, `light` or `system` |
| setup_token?<sup>7</sup> | ?string | The setup token of a new self-hosted instance (1-256 characters) |

<sup>1</sup> An address already used by any account returns the field code `EMAIL_ALREADY_IN_USE`. On a `username` instance, older apps send the username here as `name@` followed by the instance host. Any other address returns the field code `INSTANCE_ADDRESS_REQUIRED`, and the address is never stored

<sup>2</sup> Without it, Fluxer makes one from `global_name`. On a `none` [tag style](/http-api/instance/#tag-styles) instance a taken name returns the field code `USERNAME_ALREADY_TAKEN`

<sup>3</sup> A known breached password returns the field code `PASSWORD_IS_TOO_COMMON`

<sup>4</sup> Used when the instance [collects date of birth](/http-api/instance/#public-registration-fields-object). An age under the minimum for the region (13 by default) returns the field code `MUST_BE_MINIMUM_AGE`. Without it, the account joins its invite's community after it [sets one](/http-api/users/current-user/#set-date-of-birth)

<sup>5</sup> Must be true on an instance with terms or a privacy policy, or you get the field code `MUST_AGREE_TO_TOS_AND_PRIVACY_POLICY`

<sup>6</sup> Lets the person sign up while registration is closed. An unknown code returns 400 `REGISTRATION_URL_INVALID`

<sup>7</sup> Needed until the first admin account exists. A missing value returns the field code `SETUP_TOKEN_REQUIRED`, and the account that uses it gets the full [Admin ACL](/admin-api/#acl-registry)

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [authentication token response](#authentication-token-response) \| [registration pending approval response](#registration-pending-approval-response-object) | The account was created or is waiting for approval |
| 400 | [error response](/http-api/#error-response) | `CAPTCHA_REQUIRED` or `INVALID_CAPTCHA` |
| 400 | [error response](/http-api/#error-response) | `REGISTRATION_CREDENTIALS_REQUIRED` when an account waiting for approval has no password or email |
| 403 | [error response](/http-api/#error-response) | `REGISTRATION_CLOSED`, `INSTANT_ACCOUNTS_DISABLED` or `CONTENT_BLOCKED` |
| 423 | [error response](/http-api/#error-response) | `GENERAL_ERROR` when a new instance is still setting its [sign-in method](/http-api/instance/#set-the-setup-sign-in-method) |

The rate limit is 10 requests per 10 seconds, on the `auth:register` bucket.

## Verify an email code

<RouteHeader method="POST" path="/v1/auth/email-code/verify" unauthenticated />

Checks the emailed code and signs in to the existing account, or creates the account for a new address the way [register an account](#register-an-account) does, with the email already verified. A code allows 5 tries. When the code confirms an address that was never confirmed, it also ends every other session of the account, forgets its authorized IP addresses and revokes its OAuth2 grants.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| ticket | string | The ticket from [identify an account](#identify-an-account) (1-128 characters) |
| code | string | The 6-digit code from the email |
| consent?<sup>1</sup> | boolean | Whether the person accepted the terms of service, for a sign-up |
| registration_url_code? | ?string | A registration URL code from an admin, for a sign-up (1-128 characters) |
| invite_code? | ?string | An invite to open after sign-up (0-256 characters) |

<sup>1</sup> Needed when `consent_required` is true in the [identify registration](#identify-registration-object) object

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [authentication token response](#authentication-token-response) \| [MFA challenge response](#mfa-challenge-response) \| [registration pending approval response](#registration-pending-approval-response-object) | The code was accepted |
| 400 | [error response](/http-api/#error-response) | `INVALID_SIGN_IN_CODE` or `SIGN_IN_CODE_EXPIRED` |

The rate limit is 10 requests per minute, on the `auth:email_code:verify` bucket.

## Log in with a password

<RouteHeader method="POST" path="/v1/auth/login" unauthenticated />

Signs in with an email address or username and a password. Returns an [authentication token response](#authentication-token-response), or an [MFA challenge response](#mfa-challenge-response) when the account has a second factor. The request needs a [CAPTCHA](/topics/captcha/).

An unknown account and a wrong password both return the field code `INVALID_EMAIL_OR_PASSWORD`, or `INVALID_LOGIN_OR_PASSWORD` on a `username` instance.

A sign-in from a new IP address on an account without a second factor returns 403 `IP_AUTHORIZATION_REQUIRED` with a `ticket` and sends an email. Poll with [poll IP authorization](#poll-ip-authorization) until the person uses the link. Instances that send no email or turn off new-IP authorization skip this step.

Signing in turns a disabled account back on and cancels a deletion the person scheduled.

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| X-Captcha-Token? | string | The solved ALTCHA challenge, see [CAPTCHA handling](/topics/captcha/) |
| X-Fluxer-Client-Properties? | string | Base64 JSON with the app's `os`, for the [client info](#client-info-object) |
| User-Agent? | string | The client string shown in [list authentication sessions](#list-authentication-sessions) |

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| email?<sup>1</sup> | string | The email address, or the username from older apps on a `username` instance |
| login?<sup>1</sup> | string | The email address or username (1-320 characters) |
| password | string | The password (8-256 characters) |
| invite_code? | ?string | An invite to accept after a sign-in with no second factor (0-256 characters) |

<sup>1</sup> Send one of the two. On a `username` instance, `alex`, `alex#0` and `alex@` followed by the instance host all mean the same account

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [authentication token response](#authentication-token-response) \| [MFA challenge response](#mfa-challenge-response) | The credentials were accepted |
| 403 | [error response](/http-api/#error-response) | `IP_AUTHORIZATION_REQUIRED` when the IP address is new |
| 403 | [error response](/http-api/#error-response) | A suspension code with an [enforcement notice](#enforcement-notice-object), after the last factor |

The rate limit is 10 requests per 10 seconds, on the `auth:login` bucket.

## Get desktop handoff status with the poll secret

<RouteHeader method="POST" path="/v1/auth/handoff/{code}/status" unauthenticated />

Returns the [handoff status](#handoff-status-object) and, once, the new session token. Keep the token when you get it, because later polls return `expired`. A wrong secret returns `pending`.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| poll_secret | string | The secret from [initiate desktop handoff](#initiate-desktop-handoff) |
| grant? | string | The `grant` from the [handoff completion](#handoff-completion-object) link, for `deep_link` |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [handoff status](#handoff-status-object) object | The status was returned |
| 400 | [error response](/http-api/#error-response) | `INVALID_HANDOFF_CODE` when the code is malformed |
| 429 | [error response](/http-api/#error-response) | `HANDOFF_ATTEMPTS_EXCEEDED` when this IP address has 5 failed handoff attempts in 15 minutes and the poll secret is wrong, with `retry_after` |

The rate limit is 60 requests per minute, on the shared `auth:handoff:status` bucket.

## Cancel a desktop handoff

<RouteHeader method="DELETE" path="/v1/auth/handoff/{code}" unauthenticated />

Cancels a handoff and returns 204. A session that was already created stays signed in.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| poll_secret | string | The secret from [initiate desktop handoff](#initiate-desktop-handoff) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The handoff was cancelled |
| 400 | [error response](/http-api/#error-response) | `INVALID_HANDOFF_CODE`, also for a wrong secret |

The rate limit is 10 requests per minute, on the `auth:handoff:cancel` bucket.

## Create origin handoff

<RouteHeader method="POST" path="/v1/auth/origin-handoff" />

Stores encrypted app state for 2 minutes so another web origin of the same instance can take it once. Returns an [origin handoff](#origin-handoff-object) object. The sender keeps the encryption key, and Fluxer only stores the payload.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| nonce_hash | string | The SHA-256 of the receiving origin's nonce, as 64 lowercase hex characters |
| payload | string | The encrypted state as base64url (1-8,388,608 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [origin handoff](#origin-handoff-object) object | The state was stored |

The rate limit is 3 requests per 10 minutes, on the `auth:origin_handoff:create` bucket.

## Redeem origin handoff

<RouteHeader method="POST" path="/v1/auth/origin-handoff/redeem" unauthenticated />

Returns the state stored by [create origin handoff](#create-origin-handoff) as an [origin handoff payload](#origin-handoff-payload-object) object. Every attempt deletes the state, even one with a wrong nonce.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| handoff_id | string | The ID from create origin handoff, 43 base64url characters |
| nonce | string | The nonce whose SHA-256 was sent, as base64url (16-256 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [origin handoff payload](#origin-handoff-payload-object) object | The state was returned and deleted |
| 400 | [error response](/http-api/#error-response) | `INVALID_ORIGIN_HANDOFF_NONCE` when the nonce does not match |
| 404 | [error response](/http-api/#error-response) | `UNKNOWN_ORIGIN_HANDOFF` when the ID is unknown, expired or used |

The rate limit is 10 requests per minute, on the `auth:origin_handoff:redeem` bucket.
