A webhook posts messages into one guild channel under its own name and avatar. You manage webhooks with a user or bot token. To execute one, put the webhook ID and token in the path and send no `Authorization` header.

## Permissions

Management routes need [MANAGE_WEBHOOKS](/http-api/permissions/) at guild level, and `VIEW_CHANNEL` and `MANAGE_WEBHOOKS` in the webhook's channel. In a guild with an elevated [MFA level](/http-api/guilds/#mfa-levels), a caller without multi-factor authentication gets 400 `TWO_FACTOR_REQUIRED`, because `MANAGE_WEBHOOKS` is an [elevated permission](/http-api/permissions/#elevated-permissions).

A user session that doesn't declare the [`channel_threads` client capability](/http-api/threads/#client-capability) can't see webhooks of forum or media channels and gets 404 for them.

## Origin refusal

[Execute webhook](#execute-webhook), the [GitHub](#execute-github-webhook), [Slack](#execute-slack-webhook), [Instatus](#execute-instatus-webhook) and [Libredesk](#execute-libredesk-webhook) callbacks, [Get webhook message](#get-webhook-message), [Edit webhook message](#edit-webhook-message) and [Delete webhook message](#delete-webhook-message) return 403 `INVALID_API_ORIGIN` when the `Origin` header is one of the instance's own web app origins. See [cross-origin requests](/http-api/#cross-origin-requests).

## Webhook object

A webhook belongs to one guild channel. Its token never changes, and anyone with the ID and token can execute, edit or delete the webhook.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| id | snowflake | The ID of the webhook |
| guild_id | snowflake | The ID of the guild the webhook is in |
| channel_id | snowflake | The ID of the channel the webhook posts to |
| name | string | The name the webhook posts under (1-80 characters) |
| avatar | ?string | The avatar hash the webhook posts under |
| type | integer | The [webhook type](#webhook-types) |
| token?<sup>1</sup> | string | The secret token that executes the webhook (64 characters) |
| user | [partial user](/http-api/users/#partial-user-object) object | The account that created the webhook |
| source_guild?<sup>2</sup> | [webhook source guild](#webhook-source-guild-object) object | The guild of the followed announcement channel |
| source_channel?<sup>2</sup> | [webhook source channel](#webhook-source-channel-object) object | The followed announcement channel |

<sup>1</sup> Absent on a channel follower webhook

<sup>2</sup> Only on a channel follower webhook, while its creator can view the announcement channel

### Example

```json
{
  "id": "1501314428688998182",
  "guild_id": "1501314428688990000",
  "channel_id": "1501314428688991111",
  "name": "Build bot",
  "avatar": "a1b2c3d4e5f60718293a4b5c6d7e8f90",
  "type": 1,
  "token": "Xk3Qw9ZpL2vB7nR4tY6uI8oP0aS1dF5gH2jK4lZ9xC7vB1nM3qW5eR8tY0uI2oP4",
  "user": {
    "id": "1501314428688990001",
    "username": "ada",
    "discriminator": "0001",
    "global_name": null,
    "avatar": null,
    "avatar_color": null,
    "flags": 0
  }
}
```

## Webhook types

| Value | Name | Description |
| --- | --- | --- |
| 1 | INCOMING | Posts the messages its token holder sends |
| 2 | CHANNEL_FOLLOWER | Posts copies of messages published in a followed announcement channel |

[Follow announcement channel](/http-api/channels/#follow-announcement-channel) creates a channel follower webhook. You can get, update and delete it like an incoming webhook, but every token route returns 404 `UNKNOWN_WEBHOOK` for it. Copies stop arriving while its creator can't view the announcement channel.

## Webhook message body

[Execute webhook](#execute-webhook) takes this body. A body with nothing to post returns 400 `CANNOT_SEND_EMPTY_MESSAGE`. A webhook name, message content or embed text that matches the instance blocklists returns 403 `CONTENT_BLOCKED`.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| content?<sup>1</sup> | ?string | The message content |
| embeds? | array[[rich embed](/http-api/messages/#rich-embed-object) object] | Up to [max_embeds_per_message](/http-api/instance/#limit-keys) embeds (default 10) |
| attachments? | array[[pre-uploaded attachment](/http-api/messages/#pre-uploaded-attachment-object) object] | Attachment metadata |
| message_reference?<sup>2</sup> | ?[message reference input](/http-api/messages/#message-reference-input-object) object | A reply or forward reference |
| allowed_mentions?<sup>3</sup> | ?[allowed mentions](/http-api/messages/#allowed-mentions-object) object | Which mentions notify |
| flags? | integer | [Message flags](/http-api/messages/#message-flags) |
| favorite_meme_id? | ?snowflake | Accepted, but webhook messages never attach a favorite meme |
| sticker_ids? | ?array[snowflake] | Up to 3 sticker IDs |
| tts? | boolean | Accepted, but webhook messages are never text-to-speech |
| nonce?<sup>4</sup> | string \| integer | A client-generated message identifier (1-32 characters) |
| username? | ?string | A name for this message only (1-80 characters) |
| avatar_url? | ?string | An `http` or `https` avatar URL for this message only, skipped when it can't be fetched |
| thread_name?<sup>5</sup> | string | The name of a new forum post (1-100 characters) |
| applied_tags?<sup>5</sup> | array[snowflake] | The IDs of the tags for a new forum post (max 5) |

<sup>1</sup> Up to the guild's [max_message_length](/http-api/instance/#limit-keys) or 4,000 characters, whichever is larger

<sup>2</sup> The referenced message must be in the webhook's channel, or in the thread from `thread_id`

<sup>3</sup> When omitted, no mention notifies anyone

<sup>4</sup> Repeating a nonce within five minutes returns the first message and creates no new one

<sup>5</sup> Only for a webhook in a forum or media channel. See [Webhooks in forums](/http-api/forums/#webhooks-in-forums)

## Webhook message edit body

[Edit webhook message](#edit-webhook-message) takes this body. Each field you send replaces the stored value, and a body with no content, embeds or `flags` returns 400 `CANNOT_SEND_EMPTY_MESSAGE`.

| Field | Type | Description |
| --- | --- | --- |
| content? | ?string | The new message content |
| embeds? | array[[rich embed](/http-api/messages/#rich-embed-object) object] | The new embeds, where an empty array removes them all |
| flags? | integer | The new [message flags](/http-api/messages/#message-flags) |
| allowed_mentions? | ?[allowed mentions](/http-api/messages/#allowed-mentions-object) object | Ignored, and the original mentions stay |

## Create webhook

<RouteHeader method="POST" path="/v1/channels/{channel_id}/webhooks" bot auditReason />

Creates an incoming webhook in a guild text, voice, announcement, forum or media channel and returns it with its token. A guild can have [max_webhooks_per_guild](/http-api/instance/#limit-keys) webhooks (default 1,000) and a channel [max_webhooks_per_channel](/http-api/instance/#limit-keys) (default 15).

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| name | string | The webhook name (1-80 characters) |
| avatar? | ?base64 string | A base64 or data URI avatar image, up to [avatar_max_size](/http-api/instance/#limit-keys) (default 10 MiB) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [webhook](#webhook-object) object | The webhook was created |
| 400 | [error response](/http-api/#error-response) | `MAX_WEBHOOKS_PER_GUILD` or `MAX_WEBHOOKS_PER_CHANNEL` when the limit is hit |

Fluxer sends [Webhooks Update](/gateway/events/#webhooks-update) and records a `WEBHOOK_CREATE` audit log entry.

The rate limit is 10 requests per minute, on the `webhook:create::channel_id` bucket.

## Update webhook

<RouteHeader method="PATCH" path="/v1/webhooks/{webhook_id}" bot auditReason />

Updates a webhook and returns the [webhook object](#webhook-object). To move it, you need `MANAGE_WEBHOOKS` in the new channel too, and the new channel must be in the same guild.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| name? | string | The new name (1-80 characters) |
| avatar?<sup>1</sup> | ?base64 string | The new avatar image, or null to remove it |
| channel_id?<sup>2</sup> | snowflake | The channel to move the webhook to |

<sup>1</sup> Uses the same rules as [Create webhook](#create-webhook). A channel follower webhook returns 400 `INVALID_FORM_BODY` for any `avatar`

<sup>2</sup> A channel follower webhook can only move to a guild text channel that doesn't already follow the same announcement channel

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [webhook](#webhook-object) object | The webhook was updated |
| 400 | [error response](/http-api/#error-response) | `MAX_WEBHOOKS_PER_CHANNEL` when the new channel is full |
| 400 | [error response](/http-api/#error-response) | `INVALID_FOLLOW_TARGET_CHANNEL` or `CHANNEL_ALREADY_FOLLOWED` for a channel follower webhook |
| 400 | [error response](/http-api/#error-response) | `FOLLOW_TARGET_NOT_AGE_RESTRICTED` or `FOLLOW_TARGET_CONTENT_WARNING_REQUIRED` for a channel follower webhook |
| 404 | [error response](/http-api/#error-response) | `UNKNOWN_CHANNEL` when the new channel is missing or in another guild |

Fluxer sends [Webhooks Update](/gateway/events/#webhooks-update) for the old channel and, after a move, the new one. It records a `WEBHOOK_UPDATE` audit log entry.

The rate limit is 20 requests per 10 seconds, on the `webhook:update::webhook_id` bucket.

## Execute webhook

<RouteHeader method="POST" path="/v1/webhooks/{webhook_id}/{token}" />

Posts a [message](/http-api/messages/#message-object) as the webhook. Send JSON, or `multipart/form-data` to upload files.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| wait? | boolean | Whether to return the created message (default false) |
| thread_id? | snowflake | The ID of a thread in the webhook's channel to post in |

### JSON body

The body is a [webhook message body](#webhook-message-body).

### Multipart body

| Field | Type | Description |
| --- | --- | --- |
| payload_json? | string | A JSON [webhook message body](#webhook-message-body) |
| files[n]?<sup>1</sup> | binary | A file, where n is its index |
| content?<sup>2</sup> | string | The message content |
| nonce?<sup>2</sup> | string | A client-generated message identifier |
| tts?<sup>2</sup> | string | The text-to-speech flag |
| flags?<sup>2</sup> | string | The message flags |

<sup>1</sup> n runs from 0 to the [max_attachments_per_message](/http-api/instance/#limit-keys) limit minus one

<sup>2</sup> Overrides the same field in `payload_json`

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [message](/http-api/messages/#message-object) object | The message was created and `wait` is true |
| 204 | empty | The message was created and `wait` is false |
| 400 | [error response](/http-api/#error-response) | `CANNOT_SEND_EMPTY_MESSAGE` when there is nothing to post |
| 400 | [error response](/http-api/#error-response) | `WEBHOOK_FORUM_TARGET_REQUIRED` when a forum or media webhook sends no `thread_id` or `thread_name` |
| 400 | [error response](/http-api/#error-response) | `WEBHOOK_FORUM_TARGET_CONFLICT` when a forum or media webhook sends both |
| 400 | [error response](/http-api/#error-response) | `WEBHOOK_THREAD_NAME_REQUIRES_FORUM` when `thread_name` or `applied_tags` targets another channel type |
| 400 | [error response](/http-api/#error-response) | `FORUM_TAG_REQUIRED` or `NO_TAGS_AVAILABLE_TO_NON_MODERATORS` when the forum needs a tag |
| 400 | [error response](/http-api/#error-response) | `THREAD_LOCKED` or `MAX_ACTIVE_THREADS` for the target thread |
| 404 | [error response](/http-api/#error-response) | `UNKNOWN_CHANNEL` when `thread_id` is not a thread in the webhook's channel |
| 404 | [error response](/http-api/#error-response) | `UNKNOWN_FORUM_TAG` when `applied_tags` has a tag the forum doesn't have |

Fluxer sends [Message Create](/gateway/events/#message-create).

The rate limit is 60 requests per minute, on the `webhook:execute::webhook_id` bucket.

## Instatus status values

Fluxer uppercases a status and drops everything except letters, which turns `degraded_performance` into `DEGRADEDPERFORMANCE`. Each value sets the label, and every value except `UP` and `HASISSUES` also sets the embed color. Any other status is shown as sent.

| Value | Description |
| --- | --- |
| UP | Shown as "All systems operational" |
| HASISSUES | Shown as "Has issues" |
| OPERATIONAL | Shown as "Operational" |
| UNDERMAINTENANCE | Shown as "Under maintenance" |
| DEGRADEDPERFORMANCE | Shown as "Degraded performance" |
| PARTIALOUTAGE | Shown as "Partial outage" |
| MAJOROUTAGE | Shown as "Major outage" |
| INVESTIGATING | Shown as "Investigating" |
| IDENTIFIED | Shown as "Identified" |

## Execute GitHub webhook

<RouteHeader method="POST" path="/v1/webhooks/{webhook_id}/{token}/github" />

Posts one embed for a GitHub event, under the name "GitHub". Use this route's URL as the payload URL in GitHub, with the content type `application/json`. Mentions in GitHub text never notify anyone.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| thread_id? | snowflake | The ID of a thread to post in, needed for a forum or media channel |

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| X-GitHub-Event? | string | The [GitHub event type](#github-event-types) |
| X-GitHub-Delivery? | string | The delivery ID, where a repeat within 24 hours posts nothing |

### JSON body

The body is a [GitHub callback](#github-callback-object) object.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The callback was accepted, whether or not it posted a message |
| 400 | [error response](/http-api/#error-response) | `WEBHOOK_SERVICE_FORUM_UNSUPPORTED` when a forum or media webhook sends no `thread_id` |

The rate limit is 200 requests per minute, on the `webhook:github::webhook_id` bucket.

## Execute Slack webhook

<RouteHeader method="POST" path="/v1/webhooks/{webhook_id}/{token}/slack" />

Posts a message from a Slack incoming webhook body. Mentions never notify anyone, and a repeated callback posts again.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| thread_id? | snowflake | The ID of a thread to post in, needed for a forum or media channel |

### JSON body

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | the text `ok` | The message was created |

The rate limit is 60 requests per minute, on the `webhook:execute::webhook_id` bucket.
