A guild is a community with its own channels, roles, members and settings. Members and ownership are on [Guild members](/http-api/guild-members/), and channels are on [Guild channels](/http-api/guild-channels/). An OAuth2 bearer token with the [`guilds` scope](/http-api/oauth2/#oauth2-scopes) can call only [List current user guilds](#list-current-user-guilds) and [Get guild](#get-guild). A guild that doesn't exist returns 404 `UNKNOWN_GUILD`, and a route that needs membership returns 403 `MISSING_PERMISSIONS` to a non-member.

## Verification levels

The verification level decides who can send messages in the guild. The owner, bots and members with at least one role skip the check.

| Value | Name | Description |
| --- | --- | --- |
| 0 | NONE | No verification requirement |
| 1 | LOW<sup>1</sup> | The account is claimed and its email address verified |
| 2 | MEDIUM | The LOW requirement, and the account is at least 5 minutes old |
| 3 | HIGH | The MEDIUM requirement, and the membership is at least 10 minutes old |

<sup>1</sup> A guild with `DISCOVERABLE` is always at least LOW, and [Modify guild](#modify-guild) rejects a lower value with the field code `DISCOVERABLE_GUILD_VERIFICATION_LEVEL_TOO_LOW`

A member who fails the check gets 403 `GUILD_VERIFICATION_REQUIRED`, `GUILD_EMAIL_VERIFICATION_REQUIRED` or `ACCOUNT_TOO_NEW_FOR_GUILD`.

## MFA levels

| Value | Name | Description |
| --- | --- | --- |
| 0 | NONE | MFA is not required for moderation actions |
| 1 | ELEVATED | MFA is required for moderation actions |

At ELEVATED, a member other than the owner can use the [elevated permissions](/http-api/permissions/#elevated-permissions) only with an authenticator set up, and gets 400 `TWO_FACTOR_REQUIRED` without one. A bot needs its application owner to have an authenticator.

| 0 | CENTER | Center the splash card |
| 1 | LEFT | Align the splash card to the left |
| 2 | RIGHT | Align the splash card to the right |

## Visiting guilds

A visit lets someone read a guild before joining. A visitor sees the channels the @everyone role can read, with only the @everyone overwrite applied, and can't post, react, type, join voice or see the member list. Visits need the `guild_visits` [experiment assignment](/http-api/experiments/#guild-visits-assignment-object), and a session gets its visited guilds only when it identifies with the `GUILD_VISITS` [session flag](/gateway/commands/#session-flags).

A guild takes visitors while it has `VISITS_ENABLED`. A visit starts from [Visit invite guild](/http-api/invites/#visit-invite-guild), [Visit discovery guild](/http-api/discovery/#visit-discovery-guild) or the instance's single community after sign up. Visitors can't see private threads, and adult channels stay hidden from people who may not see adult content. Without a verified email, a visitor sees only the last `guild_visit_history_days_unverified` days of messages (30 by default). Search by author or mention returns 400 `SEARCH_FILTER_NEEDS_MEMBERSHIP`.

You can visit `max_guild_visits` guilds at once (10 by default, half without a verified email), and starting another ends the oldest. A visit ends in these cases, and each one sends [Guild Delete](/gateway/events/#guild-delete).

- 14 days pass without you opening it
- Its invite is deleted or expires
- You're banned
- The guild turns off `VISITS_ENABLED`

Joining the guild ends the visit and sends [Guild Create](/gateway/events/#guild-create).

## Sudo verification fields

Routes that need [sudo mode](/http-api/users/mfa/#sudo-mode) take these fields in the JSON body. You can send an earlier proof in the `X-Fluxer-Sudo-Mode-JWT` header instead, and a successful response can return a new one in that header.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| password?<sup>1</sup> | string | Current account password |
| mfa_method? | string | MFA method, one of `totp`, `webauthn` or `email_code` |
| mfa_code? | string | Authenticator or backup code when the method is `totp` (1-32 characters) |
| webauthn_response? | [WebAuthn assertion](/http-api/authentication/#webauthn-assertion) object | Assertion when the method is `webauthn` |
| webauthn_challenge? | string | Challenge bound to the WebAuthn assertion |
| email_code_ticket? | string | The ticket from [send a sudo email code](/http-api/users/mfa/#send-a-sudo-email-code) (1-128 characters) |
| email_code? | string | The 6-digit code from that email |

<sup>1</sup> Accepted only when the account has no authenticator app or passkey

A request without a proof gets 403 `SUDO_MODE_REQUIRED`, except from a bot or an account with no password, email address, authenticator or passkey.

## Create guild

<RouteHeader method="POST" path="/v1/guilds" />

Creates a guild that you own and returns the [guild object](#guild-object) without roles, channels or counts. You need a user account with a verified email address.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| name | string | Guild name (1-100 characters) |
| icon?<sup>1</sup> | ?base64 string | Guild icon |
| empty_features?<sup>2</sup> | boolean | Whether to create the guild with no features (default false) |
| template? | [guild creation template object](#guild-creation-template-object) | Roles and channels to create |

<sup>1</sup> Raw base64 or a data URL, up to the instance `avatar_max_size` limit. Animated AVIF isn't accepted

<sup>2</sup> When false, the guild starts with `ANIMATED_ICON`, `ANIMATED_BANNER`, `BANNER`, `INVITE_SPLASH` and `VISITS_ENABLED`

Without a template, the guild gets a `general` text channel, a `General` voice channel and an everyone role with the default permissions.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [guild object](#guild-object) | The guild was created |
| 400 | [error response](/http-api/#error-response) | `MAX_GUILDS`, `GUILD_TEMPLATE_INVALID`, `BOTS_CANNOT_CREATE_GUILDS` or `UNCLAIMED_ACCOUNT_CANNOT_CREATE_GUILDS` |
| 400 | [error response](/http-api/#error-response) | `SINGLE_COMMUNITY_CANNOT_CREATE_GUILDS` while the instance runs a single community |
| 403 | [error response](/http-api/#error-response) | `GUILD_CREATION_EMAIL_VERIFICATION_REQUIRED`, `CONTENT_BLOCKED` or `ACCOUNT_LIMITED` |

You get [Guild Create](/gateway/events/#guild-create) and [User Settings Update](/gateway/events/#user-settings-update) with the new guild in your folders.

The rate limit is 10 requests per minute, on the `guild:create` bucket.

## Modify guild

<RouteHeader method="PATCH" path="/v1/guilds/{guild_id}" bot auditReason mfa />

Changes guild settings and returns the updated [guild object](#guild-object). You need `MANAGE_GUILD`, which is an [elevated permission](/http-api/permissions/#elevated-permissions). Only the owner can change `mfa_level`, and it needs [sudo mode](#sudo-verification-fields).

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| name? | string | Guild name (1-100 characters) |
| icon? | ?base64 string | Guild icon, or null to clear it |
| system_channel_id? | ?snowflake | Text or announcement channel for system messages, or null to clear it |
| system_channel_flags? | integer | [System channel flags](#system-channel-flags) |
| afk_channel_id? | ?snowflake | AFK voice channel ID, or null to clear it |
| afk_timeout? | integer | AFK timeout in seconds (60-3600) |
| default_message_notifications? | integer | [Default message notification level](#default-message-notification-levels) |
| verification_level? | integer | [Verification level](#verification-levels) |
| mfa_level?<sup>1</sup> | integer | [MFA level](#mfa-levels) |
| nsfw_level?<sup>2</sup> | integer | Legacy [NSFW level](#nsfw-levels), 0 or 3 |
| nsfw? | boolean | Whether the guild is marked as adult content |
| content_warning_level? | integer | [Guild content warning level](#guild-content-warning-levels) |
| content_warning_text? | ?string | Content warning text (max 200 characters), or null for the default text |
| explicit_content_filter? | integer | [Guild explicit content filter level](#guild-explicit-content-filter-levels) |
| banner?<sup>3</sup> | ?base64 string | Guild banner, or null to clear it |
| splash?<sup>4</sup> | ?base64 string | Static invite splash, or null to clear it |
| embed_splash?<sup>4</sup> | ?base64 string | Static embedded invite splash, or null to clear it |
| splash_card_alignment? | integer | [Splash card alignment](#splash-card-alignments) |
| features?<sup>5</sup> | array[string] | The full [guild feature](#guild-features) set you want (max 100 entries) |
| message_history_cutoff? | ?ISO8601 timestamp | Earliest history visible without `READ_MESSAGE_HISTORY`, or null to hide all of it |
| password? | string | [Sudo verification](#sudo-verification-fields) password |
| mfa_method? | string | [Sudo verification](#sudo-verification-fields) method, one of `totp`, `webauthn` or `email_code` |
| mfa_code? | string | [Sudo verification](#sudo-verification-fields) authenticator code |
| webauthn_response? | [WebAuthn assertion](/http-api/authentication/#webauthn-assertion) object | [Sudo verification](#sudo-verification-fields) assertion |
| webauthn_challenge? | string | Challenge bound to the WebAuthn assertion |
| email_code_ticket? | string | The ticket from [send a sudo email code](/http-api/users/mfa/#send-a-sudo-email-code) (1-128 characters) |
| email_code? | string | The 6-digit code from that email |

<sup>1</sup> Fails with the field code `MUST_ENABLE_2FA_BEFORE_REQUIRING_FOR_MODS` when the owner has no authenticator

<sup>2</sup> `nsfw` wins when you send both

<sup>3</sup> Needs `BANNER`, and an animated banner also needs `ANIMATED_BANNER`

<sup>4</sup> Needs `INVITE_SPLASH`

<sup>5</sup> You can only add or remove `INVITES_DISABLED`, `TEXT_CHANNEL_FLEXIBLE_NAMES`, `DETACHED_BANNER`, `CLONE_EMOJI_ENABLED`, `CLONE_STICKER_ENABLED`, `HIDE_OWNER_CROWN` and `VISITS_ENABLED`, and Fluxer keeps every other feature the guild has

:::caution[Leaving out a feature you can change removes it]
Send the current `features` array with your changes applied.
:::

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [guild object](#guild-object) | The guild was updated |
| 400 | [error response](/http-api/#error-response) | `TWO_FACTOR_REQUIRED` when the guild has the [ELEVATED MFA level](#mfa-levels) and you have no authenticator |
| 403 | [error response](/http-api/#error-response) | `SUDO_MODE_REQUIRED` when changing `mfa_level` without a proof |

Every successful request sends [Guild Update](/gateway/events/#guild-update), and a request that changes something also records a [`GUILD_UPDATE`](/http-api/guild-audit-logs/#audit-actions) audit entry.

The rate limit is 20 requests per 10 seconds, on the `guild:update::guild_id` bucket.

## Delete guild

<RouteHeader method="POST" path="/v1/guilds/{guild_id}/delete" mfa />

Deletes the guild with its channels, messages, attachments, roles and invites, and returns 204. You need to be the owner and in sudo mode.

:::danger[Deleting a guild can't be undone]

:::

### JSON body

Takes the [sudo verification fields](#sudo-verification-fields), all optional.

The rate limit is 10 requests per minute, on the `guild:delete::guild_id` bucket.
