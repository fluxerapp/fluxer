Changing the email address or password takes several calls. Fluxer emails a code, you send it back with the ticket from the first call, and each step returns what the next one needs. Every route needs a user session, and bots can't use them.

On an instance where people sign in with a username (`account_identity` is `username` in the [instance features](/http-api/instance/#instance-features-object)), accounts have no email address. There the email change and password change routes return 400 `EMAIL_UNAVAILABLE_ON_INSTANCE`. Use [Set a new password](#set-a-new-password), [Get recovery kit status](#get-recovery-kit-status) and [Create a recovery kit](#create-a-recovery-kit) instead, which return 400 `USERNAME_SIGN_IN_ONLY` on an email instance.

An account linked to an instance that [enforces single sign-on](/authentication/#single-sign-on-enforcement) gets 403 `SSO_REQUIRED` from every email change and password change route, because the provider manages its email and sign-in.

## Tickets and codes

Keep these values out of logs and URLs, because anyone who has one can continue the change.

| Value | Description |
| --- | --- |
| ticket | A UUID from the first call of a flow. It belongs to one account and stops working once the flow completes |
| code | An emailed code like `ABCD-1234`, valid for 10 minutes. Send it exactly as written, in uppercase with the hyphen |
| original_proof | A UUID that proves the original address step, needed to request and verify the new address |
| verification_proof | A UUID that proves the password change code, needed to complete the change |
| email_token | A UUID for one verified new address, valid for 30 minutes and usable once |

You can resend a code 30 seconds after the previous send, and every email also counts against a per-account limit (see [Rate limits](/topics/rate-limits/)). A bad ticket, code, proof or token returns 400 `INVALID_FORM_BODY`. The [validation error](/http-api/#validation-error-object) entry has the specific code, such as `INVALID_VERIFICATION_CODE` or `VERIFICATION_CODE_EXPIRED`, and its `path` is the field.

## Email change steps

An email change goes through these steps in order. When `require_original` is false, the ticket skips the first verify step and [Start email change](#start-email-change) returns `original_proof` right away.

| Step | Call | Result |
| --- | --- | --- |
| 1 | [Start email change](#start-email-change) | A ticket and a code to the current address |
| 2 | [Verify original email](#verify-original-email) | The original address proof |
| 3 | [Request new email](#request-new-email) | A code sent to the new address |
| 4 | [Verify new email](#verify-new-email) | The email token |
| 5 | [Apply email change](#apply-email-change) | The updated user |

Calling a step out of order returns `ORIGINAL_EMAIL_MUST_BE_VERIFIED_FIRST`, `ORIGINAL_VERIFICATION_NOT_REQUIRED`, `ORIGINAL_EMAIL_ALREADY_VERIFIED` or `NO_NEW_EMAIL_REQUESTED`.

## Email change start object

A new email change ticket.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| ticket | string | The ticket for the later steps |
| require_original | boolean | Whether you must verify a code sent to the current address first. True when that address is verified |
| original_email | ?string | The current address on the account |
| original_proof | ?string | The proof, set only when `require_original` is false |
| original_code_expires_at | ?ISO8601 timestamp | When the code sent to the current address expires |
| resend_available_at | ?ISO8601 timestamp | When you can resend the code to the current address |

### Example

```json
{
  "ticket": "6f1a4c9e-3d52-4a77-9b0e-2c8f5d41ab30",
  "require_original": true,
  "original_email": "old@example.com",
  "original_proof": null,
  "original_code_expires_at": "2026-03-04T18:10:00.000Z",
  "resend_available_at": "2026-03-04T18:00:30.000Z"
}
```

## Password change completion object

The new session after a password change. Fluxer ends every session on the account, including the one that made the request, and you send later requests with this `token`. [Modify current user](/http-api/users/current-user/#modify-current-user) adds the same fields when it changes the password.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| token | string | The token for the new session |
| auth_session_id_hash | string | The base64url hash of the new session ID |

## Start email change

<RouteHeader method="POST" path="/v1/users/@me/email-change/start" />

Creates an email change ticket and, when the current address is verified, emails it a code. A claimed account with no email address gets `MUST_HAVE_EMAIL_TO_CHANGE_IT`. An instance that can't send email returns 400 `EMAIL_CODES_UNAVAILABLE` here and from [Resend original email code](#resend-original-email-code).

### JSON body

The body is empty or an empty object.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [email change start](#email-change-start-object) object | The ticket was created |

The rate limit is 10 requests per minute, on the `user:email_change:start` bucket.

## Resend original email code

<RouteHeader method="POST" path="/v1/users/@me/email-change/resend-original" />

## Request new email

<RouteHeader method="POST" path="/v1/users/@me/email-change/request-new" />

Sets the new address on the ticket and emails it a code. Calling it again with another address replaces the address on the ticket. The new address must differ from the current one, use a domain the instance allows and not belong to another account.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| ticket | string | The ticket from [Start email change](#start-email-change) (1-256 characters) |
| new_email | string | The new address (1-254 characters) |
| original_proof | string | The proof from [Start email change](#start-email-change) or [Verify original email](#verify-original-email) (1-256 characters) |
| new_password? | string | A password to check against known breached passwords. Not saved (8-256 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [new email request](#new-email-request-object) object | The code was sent to the new address |

The rate limit is 10 requests per minute, on the `user:email_change:request_new` bucket.

## Apply email change

<RouteHeader method="POST" path="/v1/users/@me/email-change/apply" mfa />

Sets the verified address on the account and returns the updated [user](/http-api/users/#user-object). A claimed account needs [sudo mode](/http-api/users/mfa/#sudo-mode), and an unclaimed account doesn't.

The token fails with `EMAIL_TOKEN_EXPIRED` after 30 minutes and `INVALID_EMAIL_TOKEN` once used.

### JSON body

The body extends the [sudo verification object](/http-api/users/mfa/#sudo-verification-object) with `email_token`.

| Field | Type | Description |
| --- | --- | --- |
| email_token | string | The token from [Verify new email](#verify-new-email) (1-256 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [user](/http-api/users/#user-object) object | The new address was set |

Fluxer sends [User Update](/gateway/events/#user-update) and emails the previous address, if there was one, a link to [revert the change](/http-api/authentication/#revert-an-email-change). Sessions and the password don't change.

The rate limit is 20 requests per minute, on the `user:email_change:apply` bucket.

## Bounced email recovery

When mail to an account's address bounces, the [user object](/http-api/users/#user-object) has `email_bounced` set to true. The three routes below set a new address without the original address step or sudo mode. Other accounts use the normal email change flow.

<RouteHeader method="POST" path="/v1/users/@me/email-change/bounced/request-new" />

Creates a ticket, sets the new address on it and emails it a code. The address is checked the same way as in [Request new email](#request-new-email).

### JSON body

| Field | Type | Description |

### Response

| Status | Body | Condition |
| --- | --- | --- |

## Complete password change

<RouteHeader method="POST" path="/v1/users/@me/password-change/complete" />

Sets the new password and returns a [new session](#password-change-completion-object). An account with TOTP or a WebAuthn credential also needs [sudo mode](/http-api/users/mfa/#sudo-mode) with that factor. A password found in known breaches fails with `PASSWORD_IS_TOO_COMMON`.

### JSON body

The body extends the [sudo verification object](/http-api/users/mfa/#sudo-verification-object) with these fields.

| Field | Type | Description |
| --- | --- | --- |
| ticket | string | The ticket from [Start password change](#start-password-change) (1-256 characters) |
| verification_proof | string | The proof from [Verify password change code](#verify-password-change-code) (1-256 characters) |
| new_password | string | The new password (8-256 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [password change completion](#password-change-completion-object) object | The password was changed |

Fluxer sends [Auth Session Change](/gateway/events/#auth-session-change) with the old and new session ID hashes.

The rate limit is 10 requests per minute, on the `user:password_change:complete` bucket.

## Set a new password

<RouteHeader method="POST" path="/v1/users/@me/password" mfa />

Changes the password on a username instance after [sudo mode](/http-api/users/mfa/#sudo-mode) and returns a [new session](#password-change-completion-object). It also deletes the account's recovery kit. A password found in known breaches fails with `PASSWORD_IS_TOO_COMMON`, and an SSO account with no password gets `PASSWORD_NOT_SET`. An instance that enforces single sign-on returns 403 `SSO_REQUIRED`.

### JSON body

The body extends the [sudo verification object](/http-api/users/mfa/#sudo-verification-object) with `new_password`.

| Field | Type | Description |
| --- | --- | --- |
| new_password | string | The new password (8-256 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [password change completion](#password-change-completion-object) object | The password was changed |

Fluxer sends [Auth Session Change](/gateway/events/#auth-session-change) with the old and new session ID hashes.

The rate limit is 10 requests per minute, on the `user:password:update` bucket.

## Create a recovery kit

<RouteHeader method="POST" path="/v1/users/@me/recovery-kit" mfa />

Creates a recovery kit after [sudo mode](/http-api/users/mfa/#sudo-mode) and makes the previous key stop working. Show the key to the person before you discard the response, because Fluxer never returns it again. An SSO account with no password gets `PASSWORD_NOT_SET`, and an instance that enforces single sign-on returns 403 `SSO_REQUIRED`.

### JSON body

The body is the [sudo verification object](/http-api/users/mfa/#sudo-verification-object).

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [recovery kit](#recovery-kit-object) object | The kit was created |

The rate limit is 6 requests per minute, on the `user:recovery_kit:create` bucket.
