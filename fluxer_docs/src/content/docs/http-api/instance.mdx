A client that knows only an instance's origin starts with [get instance discovery](#get-instance-discovery), which returns the API, Gateway and media URLs, the enabled features and the limits. Every route on this page works without a token.

## Instance discovery object

The public description of one instance.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| codename? | string | The protocol generation the instance speaks |
| api_code_version | integer | The API code version, which goes up when clients need to change their behavior |

| captcha | [captcha configuration](#captcha-configuration-object) object | CAPTCHA configuration |
| features | [instance features](#instance-features-object) object | Instance-wide feature switches |

| registration | [registration policy](#registration-policy-object) object | Who can register |

## Guild badge object

A custom badge that instance admins give to guilds. A guild lists the badges it has in `badge_ids`, and clients skip any ID that isn't in `guild_badges`.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| id | snowflake | The ID of the badge |
| name | string | The name of the badge |
| description | ?string | The tooltip text under the name, or null |
| asset_url | string | The badge image as WebP from the media proxy. Add a `size` query parameter to get it at the size you draw it |
| href | ?string | The `https` URL a click opens, or null |

## Instance notice object

### Instant account availability

| Value | Description |
| --- | --- |
| available | Sign-up can create an instant account |
| disabled | An admin turned instant accounts off |
| captcha_off | Instant accounts are on, but the CAPTCHA they need is off |
| registration_closed | Public registration is closed |
| approval_required | New accounts wait for admin approval |

### Email delivery states

| Value | Description |
| --- | --- |
| on | The instance sends email |
| off_username_mode | The instance uses usernames and never sends email |
| off_disabled | An admin or the configuration turned email off |
| off_incomplete | Email is on, but the SMTP settings or sender address are incomplete |

### Account identity modes

| Value | Description |
| --- | --- |
| email | People register and sign in with an email address |
| username | People register and sign in with a username, and the instance collects no email address |

On a `username` instance, email routes return 400 `EMAIL_UNAVAILABLE_ON_INSTANCE`. On an `email` instance, username-only routes such as [recover an account](/http-api/authentication/#recover-an-account) return 400 `USERNAME_SIGN_IN_ONLY`.

### Tag styles

| Value | Description |
| --- | --- |
| none | Usernames are unique and have no tag, and every account that isn't a bot has the discriminator `0000` |
| random | Every account gets a random tag that can be changed |

## Limit configuration object

The rules you evaluate to work out the limits for an account or a guild.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| version | integer | The format version, always `2` |
| traitDefinitions | array[string] | The trait names the instance declares |
| rules | array[[limit rule](#limit-rule-object) object] | The rules to evaluate |
| defaultsHash | string | A hash of the release's default limit values, which changes when a release changes them |

Each rule lists the keys that differ from the release defaults, plus `max_guild_emojis`, `max_guild_stickers` and their aliases whenever the rule sets them. The document doesn't include the defaults, and your client needs its own copy of them. To resolve limits, follow these steps.

1. Start with the default value of every [limit key](#limit-keys).
2. Sort the rules by the number of traits and guild features in their filters, fewest first, keeping the published order for ties.
3. Skip a rule unless every trait and guild feature it lists is present. You supply the account's traits and the guild's features yourself.
4. Expand the rule by giving every key it doesn't list the default value.
5. A rule with no filters sets each key to its value. A rule with filters raises each key to its value when that is higher.

Each key's scope decides whether a rule applies it.

| Scope | User evaluation | Guild evaluation |
| --- | --- | --- |
| user | Applied | Applied only when the rule has no guild feature filter |
| guild | Not applied | Applied when the rule has a guild feature filter or no trait filter |
| both | Applied | Applied |

Use the resolved values to show limits in your UI. The API still checks every limit and returns the endpoint's own error when a request goes over one.

## Limit rule object

### Structure

| Field | Type | Description |
| --- | --- | --- |
| id | string | The rule ID |
| filters? | [limit filters](#limit-filters-object) object | What selects the rule, omitted when it always matches |
| overrides | map[string, integer] | Values keyed by [limit key](#limit-keys). Negative values are ignored |

### Example

```json
{
  "id": "premium",
  "filters": {"traits": ["premium"]},
  "overrides": {
    "max_message_length": 4000,
    "max_guild_emojis": 250
  }
}
```

## Get instance discovery

<RouteHeader method="GET" path="/.well-known/fluxer" unauthenticated />

Returns the [instance discovery object](#instance-discovery-object). The response has `ETag` and `Last-Modified` headers, and a request with a matching `If-None-Match` or `If-Modified-Since` gets 304 with no body.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [instance discovery](#instance-discovery-object) object | The discovery document was returned |
| 304 | None | The document hasn't changed |

The rate limit is 60 requests per minute, on the `instance:info` bucket.

## Check the setup token

<RouteHeader method="POST" path="/v1/instance/setup/token-checks" unauthenticated />

Checks a setup token without using it up.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| setup_token | string | The setup token (1-256 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | None | The token is correct, or the instance needs no setup token |
| 400 | [error response](/http-api/#error-response) | The setup token is missing or wrong |
| 429 | [rate limit response](/topics/rate-limits/#rate-limit-response-object) | Too many requests, or too many wrong tokens from your IP address |

The rate limit is 10 requests per minute, on the `instance:setup:token_check` bucket.

## Set the setup sign-in method

<RouteHeader method="PUT" path="/v1/instance/setup/account-identity" unauthenticated />

Sets how people sign in on a new self-hosted instance and, for `email`, whether usernames have tags. Returns an [account identity](#account-identity-object) object. It works until one of the [account identity lock reasons](#account-identity-lock-reasons) applies, such as setup being finished or the first account existing. Send `setup_token` while `setup_token_required` is true in the [public setup state](#public-setup-state-object).

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| mode | string | The [account identity mode](#account-identity-modes) |
| tag_style? | string | One of the [tag styles](#tag-styles), `none` by default and always `none` for `username` |
| setup_token? | ?string | The setup token (1-256 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [account identity](#account-identity-object) object | The sign-in method was saved |
| 400 | [error response](/http-api/#error-response) | `TAG_STYLE_REQUIRES_EMAIL_SIGN_IN` for `random` with `username`, or the setup token is missing or wrong |
| 409 | [error response](/http-api/#error-response) | `ACCOUNT_IDENTITY_LOCKED` when the sign-in method can no longer change |
| 423 | [error response](/http-api/#error-response) | `GENERAL_ERROR` when another registration or setup call held the setup lock for 15 seconds. Retry after `Retry-After` |
| 429 | [rate limit response](/topics/rate-limits/#rate-limit-response-object) | Too many requests, or too many wrong tokens from your IP address |

The rate limit is 10 requests per minute, on the `instance:setup:account_identity` bucket.
