Every Fluxer instance comes with one LiveKit voice server inside it. You can add more, near people elsewhere or on machines with spare CPU and bandwidth.

## Plain LiveKit

A voice server is plain [LiveKit](https://docs.livekit.io/home/self-hosting/deployment/) with a config Fluxer writes. Run one of these commands where Fluxer runs. It registers the server with your instance and prints its LiveKit config.

<Tabs syncKey="runtime">
<TabItem label="Docker">

```sh
docker exec fluxer fluxerd voice-config --endpoint wss://voice.example.com > livekit.yaml
```

</TabItem>
<TabItem label="Linux with systemd">

```sh
runuser -u fluxer -- /opt/fluxer/current/bin/fluxerd voice-config --endpoint wss://voice.example.com > livekit.yaml
```

</TabItem>
<TabItem label="Kubernetes">

```sh
kubectl -n fluxer exec fluxer-0 -- fluxerd voice-config --endpoint wss://voice.example.com > livekit.yaml
```

</TabItem>
<TabItem label="With rexctl">

```sh
rexctl voice add --print --endpoint wss://voice.example.com > livekit.yaml
```

</TabItem>
</Tabs>

| Flag | What it sets |
| --- | --- |
| `--endpoint` | The address people's apps open, which needs a certificate |
| `--tcp-port`, `--udp-port` | Other media ports than 7881/tcp and 7882/udp |
| `--ip` | The public IPv4 address LiveKit gives to apps |
| `--region` | The voice region of the server |
| `--id` | The server ID. A registered server's ID prints a new config for it with a new secret |
| `--soft-limit` | The connection count after which calls prefer other servers |
| `--lat`, `--long` | The server's location, both together |

Keep the config private, because it has the server's key and secret. It also tells LiveKit to send its events to your Fluxer instance.

### Start the server

<Steps>

1. Copy the config to the voice machine and start LiveKit with it, such as with Docker.

   ```sh
   docker run -d --name livekit --restart unless-stopped --network host \
     -v "$PWD/livekit.yaml:/etc/livekit.yaml:ro" \
     livekit/livekit-server:v1.12.0 --config /etc/livekit.yaml
   ```

   [LiveKit's own binary under systemd and its Helm chart](https://docs.livekit.io/home/self-hosting/deployment/) take the same file.

2. Put a reverse proxy in front of port 7880, with a certificate for the endpoint's hostname. It needs WebSocket upgrades and a read timeout of at least 120 seconds.

   When the proxy runs on the voice machine itself, add `bind_addresses: [127.0.0.1]` to the config so LiveKit listens only there.

3. Open 7881/tcp and 7882/udp to the internet. Keep port 7880 closed to the internet, because LiveKit serves it without TLS.

4. A new server starts out draining. In the admin panel, open "Voice Servers" under Platform, edit the server and turn off "Draining". With rexctl, run `rexctl voice test <id>` to check it first, then `rexctl voice undrain <id>` to turn draining off so that new calls can use it.

</Steps>

## With rexctl on another machine

`rexctl voice join` sets this up for you, with the certificate, the firewall and upgrades.

<Steps>

1. Create a join token on the Fluxer machine.

   ```sh
   rexctl voice token
   ```

   It prints the command to run on the voice machine. The token works once and stops working after an hour, or after up to 24 hours with `--expires`.

2. Run that command on the voice machine.

   ```sh
   curl -fsSL https://fluxer.dev/install.sh | sh -s -- voice chat.example.com fvj_...
   ```

   rexctl opens the ports in ufw or firewalld, gets a certificate and tests the server. When a step fails, run the same command again.

</Steps>

:::caution[Only trusted machines]
Whoever runs a voice server can record the calls that go through it.

Give join tokens only to machines you trust.
:::

### Where it runs

| Machine | How the voice server runs |
| --- | --- |
| Debian 12 or later, or Ubuntu 22.04 or later, as root | Under systemd as `fluxer-voice.service` |
| Anywhere else | In one Docker or Podman container called `fluxer-voice` |

rexctl uses Podman when it's the only one installed, and installs Docker when neither is. Pass `--runtime systemd`, `--runtime docker` or `--runtime podman` to choose.

Both run Fluxer in voice-only mode. That starts LiveKit and the part of Fluxer that gets the certificate, and nothing more than that.

### Without root

Without root, the container runs on your own Docker or Podman account.

Rootless containers can open ports 80 and 443 only when this setting is 80 or lower.

```sh
sysctl net.ipv4.ip_unprivileged_port_start
```

If not, pass `--no-edge` and [use your own proxy](#a-voice-machine-with-its-own-web-server).

### Upgrades

On a voice machine, `rexctl status`, `logs`, `restart` and `doctor` work for the servers there. A voice machine doesn't upgrade with the Fluxer machine, so run `rexctl upgrade` or `rexctl auto-upgrade on` there as well.

An upgrade drains every server on the machine and waits up to 15 minutes for calls to end. It then moves the machine to your instance's release.

### Older voice machines

Voice machines set up with an older rexctl run each server in its own Docker container, and keep doing so. To move one to systemd or to one container, run one of these on it.

```sh
rexctl migrate --to systemd
rexctl migrate --to docker
```

The endpoints, keys and ports stay the same, and the Fluxer machine needs no change. rexctl drains the servers first. It goes back to the old containers if the new ones don't start.

## On the Fluxer machine

On a systemd install with rexctl, you can add a server next to Fluxer.

```sh
rexctl voice add
rexctl voice add --new-region fra --region-name Frankfurt --lat 50.1 --long 8.7
```

rexctl picks the ID, ports, keys and a path on your domain and asks once. A server here shares the machine's CPU with Fluxer.

It helps most when you give it a second public address with `--ip`.

Open the ports it prints in your provider's firewall as well. Its test can't see that firewall.

## Hostnames

Without a hostname, a joined server uses the machine's IPv4 address with a short-lived certificate. To use a hostname, point its `A` and `AAAA` records at the machine and pass `--hostname`, or switch later with `rexctl voice hostname <id> <host>`. On Cloudflare, set the record to "DNS only". Every server on one voice machine uses the same address.

## IPv6

A voice machine under systemd or in one container offers IPv4 and IPv6 when it has both. Callers with IPv6 only need an `AAAA` record for the voice machine's hostname.

## TURN servers

A TURN server relays calls for people who can't connect to a voice server directly. Fluxer doesn't run one. Add yours with the `FLUXER_LIVEKIT_TURN_SERVERS` [setting](/operator/settings/#fluxer_livekit_turn_servers), or with rexctl on the Fluxer machine, and every voice server of your instance gives it to apps.

A plain LiveKit server gets the TURN servers in its config file. After you add or remove one, run the command from [Plain LiveKit](#plain-livekit) again with `--id <id>` of that server, then restart LiveKit so it loads the new config file.

```sh
rexctl voice turn add --host turn.example.com --secret-file secret.txt
rexctl voice turn list
```

With `--secret-file`, set the same secret as `static-auth-secret` and turn on `use-auth-secret` in coturn. For networks that only allow port 443, add an entry with `--protocol tls --port 443` to the list.

## Ports and firewalls

| Port | Use |
| --- | --- |
| 7880/tcp | Signalling, behind your proxy and closed to the internet |
| 7881/tcp | Media, from this port up, one for each server |
| 7882/udp | Media, from this port up, one for each server |
| 80/tcp, 443/tcp | The certificate and the endpoint, on a voice machine with its own certificate |

Behind a router, forward each port to the same number on the machine.

A machine behind CGNAT usually can't take calls.

On the Fluxer machine, `rexctl voice test <id>` joins a throwaway room on a server from outside. It reports whether UDP and TCP each connect.

## A voice machine with its own web server

When nginx, another program or a Fluxer instance on the same machine has ports 80 and 443, pass `--no-edge` and your proxy's address.

```sh
rexctl voice join chat.example.com fvj_... --no-edge --endpoint wss://voice.example.com/livekit-fra-server-1
```

LiveKit then listens without TLS on `127.0.0.1` from 7880 upwards, or on `--http-bind`. Point the path at it with WebSocket upgrades and a read timeout of at least 120 seconds.

## Run without the bundled voice server

Set `FLUXER_LIVEKIT_BUNDLED=false`, or run `rexctl config set voice.bundled false`. Calls then go only to the servers you add, and can't start until you add one. `FLUXER_LIVEKIT_ENABLED=false` turns calls off.

## Look after servers

| Command | What it does |
| --- | --- |
| `rexctl voice list` | Shows every server |
| `rexctl doctor` | Checks the servers and says how to fix what it finds |
| [`rexctl voice drain`, `resync` and `set`](/operator/rexctl/#rexctl-voice) | Change one server |
| `rexctl voice remove <id>` | On the machine that runs the server, drains it, unregisters it and deletes it |
| `rexctl voice remove <id> --forget` | On the Fluxer machine, removes a plain LiveKit server or one on a machine that's gone |

Bot protection, such as Cloudflare's, has to let voice machines through to `/`, `/.well-known/fluxer`, `/api/voice/` and `/api/webhooks/livekit`.
