## rexctl auto-upgrade

Show whether rexctl upgrades Fluxer, or the voice servers on a voice machine, by itself, when it runs next and how the last run went. Each run is `rexctl upgrade --yes` and works like an upgrade you run yourself.

Run `rexctl auto-upgrade`

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |

### rexctl auto-upgrade off

Stop upgrading Fluxer by itself, along with the monthly full backup from `--full-backup`.

Run `rexctl auto-upgrade off`

### rexctl auto-upgrade on

Run `rexctl upgrade --yes` by itself with a systemd timer, or with cron on machines without systemd. On a terminal rexctl asks how often, at what time, what the backup before each upgrade holds and where to send notices. Scripts can pass those choices as flags, and a flag you leave out keeps what you chose before.

Each run backs up your instance first, and goes back to the release you had when the new one doesn't start. A scheduled run is skipped while another rexctl command is changing the instance, and the next one tries again.

With `--notify`, rexctl posts JSON to the address when an upgrade installs a new release, fails, or waits for something from you first.

The JSON holds the instance, the status (upgraded, failed or needs-move), the release, the title, the type of notice (success, failure, warning or info), and the message in each of the fields text, content, message and body.

Slack and Discord webhooks, Gotify and the Apprise API show it as it is. Pass a Gotify address like `https://gotify.example.com/message?token=...` or an Apprise address like `https://apprise.example.com/notify/your-key` for those two services.

For ntfy, add `?tpl=1&m={{.text}}` to the topic address. Put an address with ? or & in it in single quotes, so the shell passes it whole. Pass `--notify off` to stop the notices.

Run `rexctl auto-upgrade on`

```sh title="Examples"
rexctl auto-upgrade on

rexctl auto-upgrade on --at 04:00 --day sun

rexctl auto-upgrade on --notify 'https://ntfy.sh/your-topic?tpl=1&m={{.text}}'
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--at string` |  | Time of day to upgrade, as `HH:MM` in this machine's time zone. Separate several times with commas, like `06:00,18:00`. |
| `--backup string` |  | What the backup before each upgrade holds, full, without-uploads or off. |
| `--day string` |  | Run once a week on this day, like sun. Pass `daily` to run every day. |
| `--full-backup string` |  | Pass `monthly` to also make a full backup with uploads on the 1st of every month, or off. |
| `--notify string` |  | Web address rexctl posts to when an upgrade installs a new release, fails or waits for you, or off. |

### rexctl auto-upgrade test-notify

Post a test notice to the address you passed to `rexctl auto-upgrade on --notify`, with status `test`. It looks like the notice after an upgrade, so you can check that notices get to you without waiting for a new release.

Run `rexctl auto-upgrade test-notify`

## rexctl backup

Back up your instance in one file that restores on this machine or a new one, with the database, search data and uploads that Fluxer stores itself. Fluxer pauses during the copy.

Run `rexctl backup`

### rexctl backup copy-to

Copy a backup to another machine over SSH. Without a file, rexctl copies your newest backup, including the ones Fluxer makes inside its container. It uses scp, so you need an account on the other machine. With `--age-recipient`, rexctl encrypts the copy with age first. To decrypt it, run `rexctl restore --age-identity` with the matching age key file.

Run `rexctl backup copy-to <user@host:/folder> [file]`

```sh title="Examples"
rexctl backup copy-to --age-recipient age1... backup@storage.example.org:/srv/fluxer

rexctl backup copy-to backup@storage.example.org:/srv/fluxer chat.example.org-20261114-1612.tar.zst
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--age-recipient stringArray` |  | Encrypt the copy for this age public key, which you can pass more than once. |

### rexctl backup keep

Show or change how many backups rexctl keeps. After each backup, rexctl deletes the oldest ones beyond this number, except the backup that `rexctl rollback` needs and the newest backup with uploads. Pass `all` to keep every backup.

Run `rexctl backup keep [count|all]`

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |

### rexctl backup list

List your backups.

Run `rexctl backup list`

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |

### rexctl backup location

Show the folder rexctl saves backups in, or pass a full path to save new backups there. Backups that are already saved stay where they are.

Run `rexctl backup location [folder]`

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |

### rexctl backup schedule

Show or change when rexctl backs up your instance by itself. With daily it backs up every night at about `03:00`, with weekly every Sunday at about `03:00`, and off stops it. Each run works like `rexctl backup`. rexctl keeps as many as `rexctl backup keep` says.

Run `rexctl backup schedule [daily|weekly|off]`

```sh title="Examples"
rexctl backup schedule

rexctl backup schedule daily

rexctl backup schedule off
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |

### rexctl backup verify

Check that a backup is complete and readable.

Run `rexctl backup verify <file>`

## rexctl boot

Show whether a systemd service starts Fluxer when this machine starts. Docker already starts Fluxer again after a restart, and the service also starts its services in order and stops them cleanly. Podman has no daemon, so it needs the service. A systemd install always runs as a service, and this shows whether it starts with the machine.

Run `rexctl boot`

```sh title="Examples"
rexctl boot

rexctl boot on

rexctl boot off
```

### rexctl boot off

Remove the systemd service that starts Fluxer with this machine, and the copy of rexctl in `/usr/local/libexec/rexctl/rexctl` if nothing else uses it. With Docker, Docker still starts Fluxer again after a restart. On a systemd install Fluxer keeps running, but no longer starts with the machine. rexctl lists every change and asks first, unless you pass `--yes`.

Run `rexctl boot off`

```sh title="Examples"
rexctl boot off

rexctl boot off --yes
```

### rexctl boot on

Write a systemd service that starts Fluxer when this machine starts and stops it cleanly when it shuts down. On a root install it also copies rexctl to `/usr/local/libexec/rexctl/rexctl` for the service to run. On a systemd install it turns on the service that Fluxer already runs as. rexctl lists every change and asks before it makes them, unless you pass `--yes`.

Run `rexctl boot on`

```sh title="Examples"
rexctl boot on

rexctl boot on --yes
```

## rexctl config

Read and change Fluxer's settings. On a terminal, `rexctl config` opens a browser of every setting, grouped by what it changes. Pick one to see what it takes and change it.

Run `rexctl config`

```sh title="Examples"
rexctl config

rexctl config list email

rexctl config set registration.mode invite
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |

### rexctl config edit

Opens the settings you changed from their defaults as setting=value lines in `$VISUAL` or `$EDITOR`. Add a line for any other setting `rexctl config set` takes, or remove one to go back to its default. rexctl checks them as `rexctl config set` does, says what restarts and applies them once you agree.

Nothing changes until your draft passes the check. With `--compose`, it opens `custom.compose.yml` instead, for changes to Fluxer's containers that no setting covers.

Run `rexctl config edit`

```sh title="Examples"
rexctl config edit

EDITOR=vim rexctl config edit

rexctl config edit --compose
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--compose` |  | Edit `custom.compose.yml`, the Compose overrides of a Docker or Podman instance. |

### rexctl config get

Show a setting, what it takes and when it applies.

Run `rexctl config get <setting>`

```sh title="Examples"
rexctl config get edge.bind

rexctl config get storage.secret_key --reveal
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |
| `--reveal` |  | Print a secret rexctl keeps. |

### rexctl config list

List the settings people change most and the ones you changed, with their values, grouped into Network, Email, Voice, Storage, Accounts, Branding and Advanced.

Pass `--all` to list every setting. Pass a word to search every setting for ones whose name or help has it, or a group name to show one group.

Run `rexctl config list [filter]`

```sh title="Examples"
rexctl config list

rexctl config list --all

rexctl config list voice

rexctl config list --changed
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--all` |  | List every setting. |
| `--changed` |  | Only show settings that differ from their defaults. |
| `--json` |  | Print JSON. |

### rexctl config rotate

Replace the key that signs attachment links, without breaking links people already have. rexctl adds a new key, restarts the media services so every part can check it, then signs with it. The old key keeps checking older links. A day later, run it again with `--finish` to drop the old key. Data package links signed with it stop working then.

Run `rexctl config rotate media-signing-key`

```sh title="Examples"
rexctl config rotate media-signing-key

rexctl config rotate media-signing-key --finish
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--finish` |  | Drop the old keys and keep only the one that signs. |

### rexctl config set

Change one or more settings. Leave the value out on a terminal and rexctl asks for it, with what the setting takes and its current value. Pass - as the value to read a secret from stdin, which keeps it out of your shell history.

Run `rexctl config set <setting> [value] | <setting>=<value>...`

```sh title="Examples"
rexctl config set registration.mode invite

rexctl config set edge.bind=127.0.0.1:8081 edge.trusted_proxies=10.0.0.5

rexctl config set storage.secret_key -
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--migrate-identities` |  | When `sso.issuer` changes, move SSO links to the new issuer. |
| `--no-migrate-identities` |  | When `sso.issuer` changes, leave SSO links on the old issuer. |

### rexctl config unset

Go back to the default for one or more settings.

Run `rexctl config unset <setting>...`

```sh title="Examples"
rexctl config unset edge.trusted_proxies

rexctl config unset memory.profile disk.profile
```

## rexctl detach

Writes `compose.yaml` and `fluxer.env` into the instance folder in the same form as the files each Fluxer release publishes, starts Fluxer from them and stops rexctl from changing the instance. Your data stays in the same volume. Automatic upgrades stop, and a backup schedule moves into Fluxer, which keeps the backups in its volume.

Run `rexctl detach`

```sh title="Examples"
rexctl detach --yes

rexctl detach --dir /opt/fluxer2
```

### rexctl email set

Set the SMTP server Fluxer sends email through. Anything you leave out keeps its saved value, except that a new server or port without `--tls` uses the usual encryption for that port. rexctl tests them before saving, so a typo doesn't stop the email Fluxer already sends.

```sh title="Examples"

rexctl email set --ca-file my-ca.pem
```

| Flag | Default | What it does |
| --- | --- | --- |

| `--from string` |  | Sender, like Example Chat \<noreply@chat.example.com>. |
| `--host string` |  | The SMTP server. |
| `--password-file string` |  | File with the SMTP password, or - for stdin. |
| `--port string` |  | The SMTP port, 587 when nothing is saved. |
| `--tls string` |  | How the connection is encrypted (starttls, implicit, opportunistic or none). Picked from the port when left out. |
| `--username string` |  | The username for the SMTP server, or empty for none. |

## rexctl migrate

Move your instance to the new layout, off Valkey or SeaweedFS, or onto one Rust process. With `--to`, an instance in the older layout moves to one container on Docker or Podman, or to the systemd service. rexctl shows what each change saves and removes, backs up your instance first, moves the data, checks it and goes back if anything goes wrong.

A move to one container runs as the account that runs the instance now. The move to the systemd service runs as root, and so does every command for the new instance. After the move off SeaweedFS, uploads stay read-only until you open them with `--open-writes`.

The old data stays until you remove it with `--clean-up` after a newer backup.

Run `rexctl migrate`

| Flag | Default | What it does |
| --- | --- | --- |

List the TURN servers.

Run `rexctl voice turn list`

| Flag | Default | What it does |
| --- | --- | --- |
| `--json` |  | Print JSON. |

### rexctl voice turn remove

Remove a TURN server.

Run `rexctl voice turn remove [host]`

```sh title="Examples"
rexctl voice turn remove turn.example.com

rexctl voice turn remove turn.example.com --port 5349

rexctl voice turn remove --all
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--all` |  | Remove every TURN server. |
| `--port int` |  | Remove only the entry on this port. |

### rexctl voice undrain

Send new calls to a voice server again.

Run `rexctl voice undrain <id>`

```sh title="Examples"
rexctl voice undrain fra-server-2
```
