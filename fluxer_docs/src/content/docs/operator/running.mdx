A few commands check on Fluxer, read its logs, restart parts of it and help people back into their accounts. Pick the tab for the way you run Fluxer.

## Where the commands run

| How you run Fluxer | What to use |
| --- | --- |
| Docker Compose | The first Docker command, run in the folder with `compose.yaml` |
| [`docker run`](/operator/docker/#without-compose) | The second Docker command |
| [Linux by hand](/operator/linux-manual/) | The unit `fluxerd` |
| rexctl on systemd | The rexctl commands with `sudo` in front, or the unit `fluxer` |
| rexctl on Docker or Podman | The rexctl commands, as the account that installed Fluxer |

Root manages a rexctl install on systemd, so its rexctl commands need `sudo`. With Podman without root, the instance belongs to your account, so leave out `sudo`. With rexctl on systemd, you can also use the plain systemd commands `systemctl status fluxer` and `journalctl -u fluxer`.

## Status

<Tabs syncKey="runtime">
<TabItem label="Docker">

```sh
docker compose exec fluxer fluxerd ps
docker exec fluxer fluxerd ps
```

</TabItem>
<TabItem label="Linux by hand">

```sh
systemctl status fluxerd
runuser -u fluxer -- /opt/fluxer/current/bin/fluxerd ps
```

</TabItem>
<TabItem label="Kubernetes">

```sh
kubectl -n fluxer exec fluxer-0 -- fluxerd ps
```

</TabItem>
<TabItem label="With rexctl">

```sh
rexctl status
```

</TabItem>
</Tabs>

- `fluxerd ps` lists every part of Fluxer with its state and restarts. Under systemd it adds how often the unit running Fluxer restarted, `fluxer.service` with rexctl and `fluxerd.service` by hand. It ends with a line when a newer release is out, once you have turned on the daily [release check](/operator/upgrades/#turning-the-check-on).
- `fluxerd version` then shows the upgrade command, and on a rexctl install `rexctl status` shows a New release row.
- `fluxerd health` exits with 0 when every part of Fluxer is ready.
- Under systemd, `systemctl status fluxer` with rexctl or `systemctl status fluxerd` by hand has a `Status` line. It says `starting`, `ready`, `degraded`, `stopping` or `stopped`, and lists the parts that are not healthy.

## Logs

<Tabs syncKey="runtime">
<TabItem label="Docker">

```sh
docker compose logs fluxer
docker compose exec fluxer fluxerd logs api
```

With `docker run`, use `docker logs fluxer` for the whole log and `docker exec fluxer fluxerd logs api` for one part.

</TabItem>
<TabItem label="Podman">

```sh
journalctl --user -u fluxer
podman exec fluxer fluxerd logs api
```

These commands are for the [Quadlet file](/operator/platforms/podman/). As root, leave out `--user`. With `podman run`, `podman logs fluxer` shows the whole log.

</TabItem>
<TabItem label="Linux by hand">

```sh
journalctl -u fluxerd
runuser -u fluxer -- /opt/fluxer/current/bin/fluxerd logs api
```

</TabItem>
<TabItem label="Kubernetes">

```sh
kubectl -n fluxer logs fluxer-0
kubectl -n fluxer exec fluxer-0 -- fluxerd logs api
```

</TabItem>
<TabItem label="With rexctl">

```sh
rexctl logs
rexctl logs api
```

</TabItem>
</Tabs>

The first command shows every part and the second only one. Add `-f` to follow new lines.

Each of these [parts](/operator/how-it-works/#what-runs) has its own logs.

| Part | What it is |
| --- | --- |
| `postgres` | PostgreSQL with all of Fluxer's data |
| `api` | The HTTP API and the background worker |
| `gateway` | The WebSocket connections for live updates |
| `media-proxy` | Resizes and serves images and other media |
| `rust` | Eight smaller services in one process. An older instance shows them as separate parts |
| `meilisearch` | Message and member search |
| `livekit` | The voice and video server |
| `valkey` | Cache and rate limits, on older installs that still use it |
| `seaweedfs` | Uploads, on older installs that still use it |

Fluxer stops every part and PostgreSQL last, which can take up to 130 seconds. Give it that long, and never stop it with `docker rm -f` or `kill -9`.

## Invite people

A new instance lets only people with an invite link create an account. There are two kinds of invite link, and new people usually need both.

- An account invite lets someone create an account. Only admins can make one.
- A community invite lets someone who already has an account join one community. Anyone allowed to invite in that community can make one, as on fluxer.com.

<Tabs syncKey="admin-tool">
<TabItem label="Admin panel">

Open the admin panel at `https://chat.example.com/admin` with your domain, and sign in with your admin account. Under Configuration, open "Instance Config".

In the "Registration Controls" card, use "Create Admin-Issued Registration URL", with a label, how many days it works and how many people can use it. You can also pick a community that people join right after they sign up.

The new link appears under "Existing Registration URLs", where "Copy URL" copies it and "Revoke" stops it working. "Registration Policy" in the same card changes who can sign up.

</TabItem>
<TabItem label="With rexctl">

```sh
rexctl invites create --uses 10 --expires 7d
rexctl registration set approval
```

`rexctl invites create` prints the link. `rexctl registration set` sets who can sign up, to `open`, `approval`, `invite` or `closed`.

</TabItem>
</Tabs>

To make a community invite, open the community in the app, open its menu and choose "Invite members", which gives you a link.

## How people join

Send each person the account invite link. It opens your instance in their browser, where they create an account and can use Fluxer right away.

In the apps, people choose your instance on the sign-in screen and enter your domain, such as `chat.example.com`, as the instance address. Notifications on the mobile apps need the [push relay](/operator/how-it-works/#the-push-relay), which the setup wizard asks about. Your instance encrypts these notifications so that only your instance and the device they're for can read them. Fluxer, Apple and Google pass them on without being able to read them, but they can still see that a notification was sent, when it was sent and the device it's for.

## Help someone back into their account

When someone can't reset their own password, create a reset link for them. It works once for an hour, so send it over a channel you trust. It also works for your own admin account.

Fluxer records the link in the audit log under the account, without the link itself.

<Tabs syncKey="runtime">
<TabItem label="Docker">

```sh
docker compose exec fluxer fluxerd users reset-link alex
docker exec fluxer fluxerd users reset-link alex
```

</TabItem>
<TabItem label="Podman">

```sh
podman exec fluxer fluxerd users reset-link alex
```

</TabItem>
<TabItem label="Linux by hand">

```sh
runuser -u fluxer -- /opt/fluxer/current/bin/fluxerd users reset-link alex
```

</TabItem>
<TabItem label="Kubernetes">

```sh
kubectl -n fluxer exec fluxer-0 -- fluxerd users reset-link alex
```

</TabItem>
<TabItem label="With rexctl">

```sh
rexctl users reset-link alex
```

On systemd, put `sudo` in front.

</TabItem>
</Tabs>

Pass a username, an email address or a user ID.

In the admin panel, open Users under Lookup and find the account. On its Account tab, "Create Password Reset Link" shows the same kind of link. Scripts can use [Create password reset link](/admin-api/users/#create-password-reset-link) in the admin API, with a key from "Admin API Keys" under Configuration. [Lost passwords work differently](/operator/sign-in/#lost-passwords) on instances with email or single sign-on.

## Move to a new machine

Fluxer asks Let's Encrypt for a certificate when it starts, and that only works once your domain points at the machine. Move in this order.

1. A day before, lower the TTL of your domain's DNS records, such as to 5 minutes.
2. Take a backup and stop Fluxer on the old machine right away. Anything people post after the backup stays on the old machine.
3. On the new machine, [restore the backup](/operator/backups/#restore) with the same domain, and don't start Fluxer until your domain's DNS records point there.
4. Point your domain's DNS records at the new machine's IP address.
5. Start Fluxer there. It gets its certificate once the new records are out.

Don't start the old instance again. With rexctl, run `rexctl restore` or the `install.sh ... restore` command after step 4, because it starts Fluxer right away.

A backup restores into any way of running Fluxer, so this can also move an instance between Docker, systemd and Kubernetes.
