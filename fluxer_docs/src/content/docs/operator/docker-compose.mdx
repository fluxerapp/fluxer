Use this page if your platform runs compose stacks for you, such as Portainer, TrueNAS or Unraid, and you can't run rexctl on the machine. When you can run rexctl, [install with rexctl](/operator/) instead, because it does all of this for you.

## Get the files

Every release comes with a compose bundle. Download the latest one into an empty folder and unpack it.

```sh
curl -fsSL https://fluxer.dev/compose/latest -o fluxer-compose.tar.gz
tar -xzf fluxer-compose.tar.gz
cp .env.example .env
```

The bundle has `docker-compose.yml` with every Fluxer image pinned to the release, the `Caddyfile`, a few optional compose files and `.env.example`. The bundle for each version is also on its release on [GitHub](https://github.com/fluxerapp/fluxer/releases).

## Fill in .env

Set `FLUXER_DOMAIN` to your instance's domain, such as `chat.example.com`. Then run these commands in the folder to fill in the secrets.

```sh
for key in POSTGRES_PASSWORD MEILI_MASTER_KEY FLUXER_S3_SECRET_KEY FLUXER_SUDO_MODE_SECRET \
  FLUXER_CONNECTION_INITIATION_SECRET FLUXER_PROFILE_PSEUDONYM_SECRET FLUXER_GATEWAY_RPC_AUTH_TOKEN \
  FLUXER_ERLANG_COOKIE FLUXER_MEDIA_PROXY_SECRET_KEY FLUXER_ADMIN_SECRET_KEY_BASE \
  FLUXER_ADMIN_OAUTH_CLIENT_SECRET LIVEKIT_API_SECRET; do
  sed -i "s|^$key=.*|$key=$(openssl rand -hex 32)|" .env
done
sed -i "s|^FLUXER_SETUP_TOKEN=.*|FLUXER_SETUP_TOKEN=$(openssl rand -hex 32)|" .env
sed -i "s|^FLUXER_MEDIA_PROXY_UPLOAD_RELAY_SECRET_BASE64=.*|FLUXER_MEDIA_PROXY_UPLOAD_RELAY_SECRET_BASE64=$(openssl rand -base64 32)|" .env
sed -i "s|^FLUXER_ACTIVITYPUB_SIGNING_KEY_BASE64=.*|FLUXER_ACTIVITYPUB_SIGNING_KEY_BASE64=$(openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -outform DER | base64 | tr -d '\n')|" .env
openssl ecparam -name prime256v1 -genkey -noout -out vapid.pem
sed -i "s|^FLUXER_VAPID_PUBLIC_KEY=.*|FLUXER_VAPID_PUBLIC_KEY=$(openssl ec -in vapid.pem -pubout -outform DER 2>/dev/null | tail -c 65 | base64 | tr '/+' '_-' | tr -d '=\n')|" .env
sed -i "s|^FLUXER_VAPID_PRIVATE_KEY=.*|FLUXER_VAPID_PRIVATE_KEY=$(openssl ec -in vapid.pem -outform DER 2>/dev/null | tail -c +8 | head -c 32 | base64 | tr '/+' '_-' | tr -d '=\n')|" .env
rm vapid.pem
```

You can put [every other setting](/operator/environment/) in `.env` too.

Keep a copy of `.env` somewhere safe. The database, search and push keys can't change once Fluxer has started. Your data depends on them. If your platform has its own place for environment values, paste the lines from `.env` there.

## Start it

Open TCP ports 80, 443 and 7881 and UDP ports 443 and 7882, the same as for a [rexctl install](/operator/). Then start Fluxer.

```sh
docker compose up -d
```

Fluxer serves your domain over HTTPS and gets its own certificate. If another web server already uses ports 80 and 443, add these two lines to `.env` before you start, and point your proxy at `127.0.0.1:8080` as described in [Put Fluxer behind your own proxy](/operator/reverse-proxy/).

```sh
COMPOSE_FILE=docker-compose.yml:docker-compose.proxy.yml
FLUXER_EDGE_BIND=127.0.0.1:8080
```

When every service is healthy, open your domain in a browser and enter the `FLUXER_SETUP_TOKEN` from `.env` to create your admin account.

The `voice` folder of the bundle runs extra LiveKit servers on this machine or on others. See [Run a voice server with Docker Compose](/operator/voice-compose/).

## Upgrade

Download the new bundle into the same folder and unpack it, which replaces every file except `.env`. If the new `.env.example` has an uncommented line your `.env` doesn't have yet, add it, then run `docker compose up -d`.

[Make a backup](#back-up-and-restore) before you upgrade.

## Back up and restore

`rexctl backup` and `rexctl restore` aren't available without rexctl. If you can run rexctl on the machine, [switch to rexctl](#switch-to-rexctl-later) and use those. Otherwise, back up these by hand:

- the database, as a dump made with `pg_dump`
- the volumes `seaweedfs-data` (uploads), `meilisearch-data` (search), `valkey-data` and `nats-data`
- `.env`, and any files you changed in the folder, such as `Caddyfile` or `caddy.d`

The compose file gives the project the name `fluxer`, so the volumes are called `fluxer_seaweedfs-data` and so on. Some platforms give the project another name. Check the names with `docker volume ls`. With `filesystem-object-store.compose.yml`, uploads are in `objects-data`. With `kv-postgres.compose.yml`, there's no `valkey-data`. When uploads are in your own object store, back them up with that store's tools.

### Make a backup

Run these commands in the folder. Fluxer keeps running while the database is dumped and stops while the volumes are copied.

```sh
mkdir -p backup
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > backup/fluxer.dump
docker compose stop
for v in seaweedfs-data objects-data meilisearch-data valkey-data nats-data; do
  docker volume inspect "fluxer_$v" > /dev/null 2>&1 || continue
  docker run --rm -v "fluxer_$v":/v:ro -v "$PWD/backup":/b alpine tar -czf "/b/$v.tar.gz" -C /v .
done
docker compose up -d
cp .env backup/
```

Copy the `backup` folder to another machine or disk.

### Restore a backup

Restore with the compose bundle of the release the backup was made on, and upgrade after the restore. On a new machine, unpack that bundle into an empty folder. On the same machine, remove the old containers and volumes first. It deletes Fluxer's data on this machine. Check that the backup is complete first.

```sh
docker compose down -v
```

Put the `backup` folder in the bundle folder and copy `.env` and your changed files back. Then create the containers and volumes, restore the database into the empty one and unpack the volumes.

```sh
cp backup/.env .env
docker compose create
docker compose start postgres
until docker compose exec -T postgres sh -c 'pg_isready -q -h 127.0.0.1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'; do sleep 1; done
docker compose exec -T postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --exit-on-error --single-transaction' < backup/fluxer.dump
for f in backup/*-data.tar.gz; do
  v=$(basename "$f" .tar.gz)
  docker run --rm -v "fluxer_$v":/v -v "$PWD/backup":/b:ro alpine sh -c "find /v -mindepth 1 -delete && tar -xzf /b/$v.tar.gz -C /v"
done
docker compose up -d
```

## Switch to rexctl later

If you can run rexctl on the machine later, `rexctl takeover --dir <folder>` hands this instance to rexctl with its data and secrets as they are.
