When you host Fluxer yourself, it runs as one container, one systemd service on Debian or Ubuntu, or one pod on Kubernetes. Inside, a supervisor called fluxerd runs PostgreSQL, the API, the gateway, search, voice and the web app. Fluxer needs only a domain or an IP address from you. The first time it starts, it makes every password and key it needs.

## Which setup fits you

<SetupPicker />

Docker, systemd and Kubernetes run the same Fluxer with the same [settings](/operator/settings/) and the same `fluxerd` commands. [rexctl](/operator/with-rexctl/) is an optional helper for Docker, Podman and systemd, and [Linux by hand](/operator/linux-manual/) installs the systemd service without it.

Fluxer also runs on [other platforms](/operator/platforms/), such as a Raspberry Pi, Synology or Proxmox.

After the setup wizard, [invite people](/operator/running/#invite-people) by link.

## What you look after

- [Keep backups off the machine](/operator/backups/#copy-backups-off-the-machine). Fluxer backs up its database to the same disk before every upgrade, and on a schedule when you [set `FLUXER_BACKUP_SCHEDULE`](/operator/backups/#back-up-on-a-schedule).
- [Install new releases](/operator/upgrades/) when they come out. They fix bugs and security problems.
- Set up [email](/operator/email/) if people sign in with email. Password resets go out by email.
- Look after the communities on your instance. You and the admins you choose handle reports and moderation in the admin panel.
- Watch voice capacity. Calls use the machine's CPU and bandwidth, and [voice servers](/operator/voice-servers/) on other machines take the load off it.

A self-hosted instance runs the same code as fluxer.com, with [a few differences](/operator/security/#what-differs-from-fluxercom).

## Already on the older Compose install?

Instances that run each part of Fluxer in its own container keep working on the release they have. You can [move them](/operator/moving/) to one container or to systemd when you're ready.
