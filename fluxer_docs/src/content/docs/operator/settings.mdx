Every setting has one name, whichever way you run Fluxer. A setting without a default is off, or Fluxer works out its value from the other settings.

## Where settings go

| How you run Fluxer | Where settings go |
| --- | --- |
| Docker without rexctl | `fluxer.env` |
| systemd without rexctl | `/etc/fluxer/fluxer.env` |
| Kubernetes | Under `config` in the Helm chart |
| rexctl | [`rexctl config set`](/operator/configuration/) |

## Required

Only this setting is required. Fluxer makes its own passwords and keys when it first starts.

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_domain">
<dt>`FLUXER_DOMAIN`</dt>
<dd>The domain or IP address Fluxer runs on. rexctl also calls it `domain`.</dd>
</div>
</dl>

## First admin account

Fluxer creates the setup token on its first start. `fluxerd setup-token` prints it.

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_setup_token">
<dt>`FLUXER_SETUP_TOKEN`</dt>
<dd>The token the setup wizard asks for before it creates the first admin account. Use 32 to 256 printable characters, such as the output of `openssl rand -hex 32`. When it's empty, Fluxer creates one on its first start, and `fluxerd setup-token` prints it. Keep it secret.</dd>
</div>
</dl>

## Passwords and keys

Fluxer creates these on its first start and keeps them in its data folder, so backups have them too. Set one only to replace the value Fluxer made, and treat every backup as secret.

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_activitypub_signing_key_base64">
<dt>`FLUXER_ACTIVITYPUB_SIGNING_KEY_BASE64`</dt>
<dd>The RSA private key the unfurl service signs ActivityPub requests with when it builds link previews for fediverse posts. Use base64 DER in PKCS#8 or PKCS#1 form. When it's empty, the unfurl service makes those requests unsigned. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_admin_oauth_client_secret">
<dt>`FLUXER_ADMIN_OAUTH_CLIENT_SECRET`</dt>
<dd>The OAuth2 client secret the admin panel uses to sign in through the API. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_admin_secret_key_base">
<dt>`FLUXER_ADMIN_SECRET_KEY_BASE`</dt>
<dd>The key the admin panel signs its sessions, CSRF tokens and OAuth state with. Changing it signs everyone out of the admin panel. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_connection_initiation_secret">
<dt>`FLUXER_CONNECTION_INITIATION_SECRET`</dt>
<dd>The key that signs connection initiation tokens, data export links and admin download links. Changing it breaks tokens not yet verified and download links already sent. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_erlang_cookie">
<dt>`FLUXER_ERLANG_COOKIE`</dt>
<dd>The shared secret for Erlang distribution in the gateway. Anyone who can connect to the distribution port with this value can run code in the gateway. Keep the port private. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_gateway_rpc_auth_token">
<dt>`FLUXER_GATEWAY_RPC_AUTH_TOKEN`</dt>
<dd>The token the api, worker, gateway and push services use to authenticate internal calls to each other. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_media_proxy_secret_key">
<dt>`FLUXER_MEDIA_PROXY_SECRET_KEY`</dt>
<dd>The key that signs the `/external/` URLs for third-party media, such as link preview images and GIF results. The API also uses it to call the media proxy's internal endpoints. It doesn't sign uploaded attachments, which use `FLUXER_MEDIA_PROXY_ATTACHMENT_URL_SECRETS_BASE64`. Changing it doesn't affect anything stored, but proxy URLs that were already handed out stop working, such as link preview images in clients that are open, until they reload. Keep the value secret.</dd>
</div>
<div class="flx-setting" id="fluxer_media_proxy_upload_relay_secret_base64">
<dt>`FLUXER_MEDIA_PROXY_UPLOAD_RELAY_SECRET_BASE64`</dt>
<dd>The key that signs upload relay tokens, as standard base64 that decodes to at least 32 bytes. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_profile_pseudonym_secret">
<dt>`FLUXER_PROFILE_PSEUDONYM_SECRET`</dt>
<dd>The key Fluxer uses to derive the placeholder name and tag that others see while an account's profile is hidden. Changing it gives every hidden profile a new placeholder. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_s3_access_key">
<dt>`FLUXER_S3_ACCESS_KEY`</dt>
<dd>The object store access key. rexctl also calls it `storage.access_key`.</dd>
</div>
<div class="flx-setting" id="fluxer_s3_secret_key">
<dt>`FLUXER_S3_SECRET_KEY`</dt>
<dd>The object store secret key. For your own object store, set its secret key, and update it when you rotate the key at the store. Keep it secret. rexctl also calls it `storage.secret_key`.</dd>
</div>
<div class="flx-setting" id="fluxer_sudo_mode_secret">
<dt>`FLUXER_SUDO_MODE_SECRET`</dt>
<dd>The key Fluxer signs sudo mode tokens with and derives a few other internal signing keys from. Changing it ends every active sudo mode session, voids codes already emailed and makes every remembered device count as new. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_vapid_private_key">
<dt>`FLUXER_VAPID_PRIVATE_KEY`</dt>
<dd>The private half of the VAPID key pair for browser push notifications, as unpadded base64url of the 32-byte P-256 private key. The value is 43 characters long. It must match `FLUXER_VAPID_PUBLIC_KEY`. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_vapid_public_key">
<dt>`FLUXER_VAPID_PUBLIC_KEY`</dt>
<dd>The public half of the VAPID key pair for browser push notifications, as unpadded base64url of the 65-byte uncompressed P-256 point. The value is 87 characters long.</dd>
</div>
<div class="flx-setting" id="livekit_api_key">
<dt>`LIVEKIT_API_KEY`</dt>
<dd>The LiveKit API key. Keep it secret.</dd>
</div>
<div class="flx-setting" id="livekit_api_secret">
<dt>`LIVEKIT_API_SECRET`</dt>
<dd>The LiveKit API secret that goes with `LIVEKIT_API_KEY`, at least 32 characters. Keep it secret.</dd>
</div>
<div class="flx-setting" id="meili_master_key">
<dt>`MEILI_MASTER_KEY`</dt>
<dd>The Meilisearch master key. Keep it secret.</dd>
</div>
<div class="flx-setting" id="postgres_password">
<dt>`POSTGRES_PASSWORD`</dt>
<dd>The PostgreSQL password. Keep it secret.</dd>
</div>
</dl>

## Public address

Every address comes from `FLUXER_DOMAIN`. Set these only for a part on another address.

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_admin_endpoint">
<dt>`FLUXER_ADMIN_ENDPOINT`</dt>
<dd>The public address of the admin panel. When it's empty, Fluxer uses the public origin followed by `FLUXER_ADMIN_BASE_PATH`. The admin sign-in redirect is this address followed by `/oauth2_callback`, the single sign-on redirect is this address followed by `/sso/callback`, and the admin panel uses secure cookies when the address starts with `https`.</dd>
</div>
<div class="flx-setting" id="fluxer_api_client_endpoint">
<dt>`FLUXER_API_CLIENT_ENDPOINT`</dt>
<dd>The API base URL Fluxer hands to clients. When it's empty, Fluxer uses the public origin followed by `/api`.</dd>
</div>
<div class="flx-setting" id="fluxer_api_discovery_public_endpoint">
<dt>`FLUXER_API_DISCOVERY_PUBLIC_ENDPOINT`</dt>
<dd>The public API base URL Fluxer lists in instance discovery as `api_public`. The ActivityPub actor and its key ID use the same address, so its host must serve `/.well-known/webfinger`, and changing it on an instance with a signing key gives remote servers a new actor. When it's empty, Fluxer uses `FLUXER_API_ENDPOINT`. Webhooks, signed links and Bluesky sign-in always use `FLUXER_API_ENDPOINT`.</dd>
</div>
<div class="flx-setting" id="fluxer_api_endpoint">
<dt>`FLUXER_API_ENDPOINT`</dt>
<dd>The public base URL of the API. When it's empty, Fluxer uses the public origin followed by `/api`.</dd>
</div>
<div class="flx-setting" id="fluxer_app_endpoint">
<dt>`FLUXER_APP_ENDPOINT`</dt>
<dd>The address of the web app, which Fluxer allows through CORS and uses in links. When it's empty, Fluxer uses the public origin.</dd>
</div>
<div class="flx-setting" id="fluxer_app_origin_aliases">
<dt>`FLUXER_APP_ORIGIN_ALIASES`</dt>
<dd>More web app origins, separated by commas, for an instance that serves the web app on more than one hostname. Each must be an http or https origin. The API allows each one through CORS and accepts it for sign-in handoff. List them and the web app origin in `FLUXER_PASSKEY_ADDITIONAL_ALLOWED_ORIGINS` too, so passkeys work on them.</dd>
</div>
<div class="flx-setting" id="fluxer_gateway_endpoint">
<dt>`FLUXER_GATEWAY_ENDPOINT`</dt>
<dd>The public WebSocket URL of the gateway, starting with `ws` or `wss`. When it's empty, Fluxer uses `wss` on the public host followed by `/gateway`, or `ws` when the public scheme is `http`.</dd>
</div>
<div class="flx-setting" id="fluxer_gift_domain">
<dt>`FLUXER_GIFT_DOMAIN`</dt>
<dd>A separate hostname for gift links, with no scheme, port or path. When it's set, the default gift address uses this host.</dd>
</div>
<div class="flx-setting" id="fluxer_gift_endpoint">
<dt>`FLUXER_GIFT_ENDPOINT`</dt>
<dd>The base URL of gift links. When it's empty, Fluxer uses `FLUXER_GIFT_DOMAIN` or the public host, followed by `/gift`.</dd>
</div>
<div class="flx-setting" id="fluxer_invite_domain">
<dt>`FLUXER_INVITE_DOMAIN`</dt>
<dd>A separate hostname for invite links, with no scheme, port or path. When it's set, the default invite address uses this host.</dd>
</div>
<div class="flx-setting" id="fluxer_invite_endpoint">
<dt>`FLUXER_INVITE_ENDPOINT`</dt>
<dd>The base URL of invite links. When it's empty, Fluxer uses `FLUXER_INVITE_DOMAIN`, or the public host when that is empty, followed by `/invite`.</dd>
</div>
<div class="flx-setting" id="fluxer_marketing_endpoint">
<dt>`FLUXER_MARKETING_ENDPOINT`</dt>
<dd>The address of the marketing site, which Fluxer allows through CORS and uses in some links. When it's empty, Fluxer uses the public origin.</dd>
</div>
<div class="flx-setting" id="fluxer_media_endpoint">
<dt>`FLUXER_MEDIA_ENDPOINT`</dt>
<dd>The public address of the media proxy. When it's empty, Fluxer uses the public origin followed by `/media`.</dd>
</div>
<div class="flx-setting" id="fluxer_media_proxy_public_endpoint">
<dt>`FLUXER_MEDIA_PROXY_PUBLIC_ENDPOINT`</dt>
<dd>The public media proxy address that the gifs, unfurl and media-proxy services use when they build media links. When it's empty, they use `FLUXER_MEDIA_ENDPOINT`, or the public origin followed by `/media`.</dd>
</div>
<div class="flx-setting" id="fluxer_public_origin">
<dt>`FLUXER_PUBLIC_ORIGIN`</dt>
<dd>The origin browsers use to open the instance, as a scheme, host and optional port with no path or trailing slash, such as `https://chat.example.com:8443`. When it's set, the default public addresses of the api, worker and other services come from it. Keep `FLUXER_DOMAIN` set to the same host. The edge site address, the passkey relying party ID, the default sender and VAPID contact addresses and the gateway still use `FLUXER_DOMAIN`.</dd>
</div>
<div class="flx-setting" id="fluxer_public_scheme">
<dt>`FLUXER_PUBLIC_SCHEME`</dt>
<dd class="flx-setting-default">Default `https`</dd>
<dd>The scheme browsers use to open the instance. Use `https` or `http`. Fluxer builds public addresses from it and `FLUXER_DOMAIN` when `FLUXER_PUBLIC_ORIGIN` is empty. With `http`, also set `FLUXER_PUBLIC_PORT`, usually to `80`. Without rexctl, the edge also uses it for its default site address.</dd>
</div>
<div class="flx-setting" id="fluxer_static_cdn_domain">
<dt>`FLUXER_STATIC_CDN_DOMAIN`</dt>
<dd>A separate hostname for static assets, with no scheme, port or path. When it's set, the default static address of the api and worker services is `https://` followed by this host.</dd>
</div>
<div class="flx-setting" id="fluxer_static_cdn_endpoint">
<dt>`FLUXER_STATIC_CDN_ENDPOINT`</dt>
<dd>The origin Fluxer serves static assets such as the favicon and app icons from. When it's empty, the api and worker services derive it from `FLUXER_STATIC_CDN_DOMAIN` or the public origin, and the admin and gateway services use the public origin. The app-proxy service uses it only when it's set, and serves its own copies of the web app files otherwise.</dd>
</div>
</dl>

## Edge and HTTPS

By default Fluxer listens on ports 80 and 443 and gets its own certificate for your domain. Behind your own proxy or a tunnel, [turn on proxy mode](/operator/reverse-proxy/#turn-on-proxy-mode).

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_admin_base_path">
<dt>`FLUXER_ADMIN_BASE_PATH`</dt>
<dd class="flx-setting-default">Default `/admin`</dd>
<dd>The path the admin panel is served under, with a leading slash and no trailing slash, such as `/panel`. The edge serves the admin panel under this path, the admin service builds its links with it, and the default `FLUXER_ADMIN_ENDPOINT` follows it.</dd>
</div>
<div class="flx-setting" id="fluxer_caddy_site_address">
<dt>`FLUXER_CADDY_SITE_ADDRESS`</dt>
<dd>The old name for `FLUXER_EDGE_SITE_ADDRESS`.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_acme_ca">
<dt>`FLUXER_EDGE_ACME_CA`</dt>
<dd>The ACME directory the edge gets its certificate from. When it's empty, the edge uses Let's Encrypt.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_acme_ca_root">
<dt>`FLUXER_EDGE_ACME_CA_ROOT`</dt>
<dd>A PEM file with the CA certificate the edge trusts for the ACME directory. When it's empty, the edge uses the system trust store.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_bind">
<dt>`FLUXER_EDGE_BIND`</dt>
<dd class="flx-setting-default">Default `127.0.0.1:8080`</dd>
<dd>The address your reverse proxy or tunnel connects to in proxy and tunnel mode. In the Fluxer image the default is `0.0.0.0:8080`, and you limit who can connect where you publish the port. rexctl also calls it `edge.bind`.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_encode">
<dt>`FLUXER_EDGE_ENCODE`</dt>
<dd class="flx-setting-default">Default `zstd gzip`</dd>
<dd>The response compression the edge offers, written as the arguments of the Caddy encode directive, such as `gzip` alone.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_global_options">
<dt>`FLUXER_EDGE_GLOBAL_OPTIONS`</dt>
<dd>Extra Caddy global options on one line, added to the global block of the edge Caddyfile, such as `email admin@chat.example.com` for the certificate account. An empty value adds nothing.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_listen_address">
<dt>`FLUXER_EDGE_LISTEN_ADDRESS`</dt>
<dd>The IP address on this machine that Fluxer listens on for HTTP and HTTPS, or empty for every address. Write an IPv6 address without brackets. rexctl also calls it `edge.listen_address`.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_mode">
<dt>`FLUXER_EDGE_MODE`</dt>
<dd class="flx-setting-default">Default `bundled`</dd>
<dd>How web traffic gets to Fluxer. `bundled` serves HTTPS on ports 80 and 443 with its own certificate. `proxy` and `tunnel` serve plain HTTP on port 8080 for your own reverse proxy or tunnel.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_protocols">
<dt>`FLUXER_EDGE_PROTOCOLS`</dt>
<dd class="flx-setting-default">Default `h1 h2 h3`</dd>
<dd>The HTTP versions the edge serves, as the arguments of the Caddy protocols option, such as `h1 h2` to turn off HTTP/3.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_site_address">
<dt>`FLUXER_EDGE_SITE_ADDRESS`</dt>
<dd>The site address the edge serves, including the scheme. When it's empty, the edge uses `FLUXER_CADDY_SITE_ADDRESS`, or `FLUXER_PUBLIC_SCHEME` followed by `://` and `FLUXER_DOMAIN`.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_tls">
<dt>`FLUXER_EDGE_TLS`</dt>
<dd>The arguments of a Caddy tls directive for the edge, such as `internal` for a certificate from Caddy's own local CA, or a certificate and key path under `/etc/fluxer/certs`. When it's empty, the edge adds no tls line and Caddy gets certificates on its own.</dd>
</div>
<div class="flx-setting" id="fluxer_edge_trusted_proxies">
<dt>`FLUXER_EDGE_TRUSTED_PROXIES`</dt>
<dd class="flx-setting-default">Default `127.0.0.1/32`</dd>
<dd>Proxies whose client address headers Fluxer trusts, by default only this machine, or private ranges in proxy and tunnel mode. rexctl also calls it `edge.trusted_proxies`.</dd>
</div>
<div class="flx-setting" id="fluxer_http_port">
<dt>`FLUXER_HTTP_PORT`</dt>
<dd class="flx-setting-default">Default `80`</dd>
<dd>The port Fluxer listens on for HTTP. rexctl also calls it `edge.http_port`.</dd>
</div>
<div class="flx-setting" id="fluxer_https_port">
<dt>`FLUXER_HTTPS_PORT`</dt>
<dd class="flx-setting-default">Default `443`</dd>
<dd>The port Fluxer listens on for HTTPS. If people connect to this port directly, set `FLUXER_PUBLIC_PORT` to the same port. rexctl also calls it `edge.https_port`.</dd>
</div>
<div class="flx-setting" id="fluxer_public_port">
<dt>`FLUXER_PUBLIC_PORT`</dt>
<dd class="flx-setting-default">Default `443`</dd>
<dd>The port people use in Fluxer's address, when it differs from the one Fluxer listens on. rexctl also calls it `edge.public_port`.</dd>
</div>
</dl>

## Voice and video

Calls connect to the machine on `FLUXER_LIVEKIT_TCP_PORT` and `FLUXER_LIVEKIT_UDP_PORT`, also when Fluxer is behind your own proxy.

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_livekit_bundled">
<dt>`FLUXER_LIVEKIT_BUNDLED`</dt>
<dd class="flx-setting-default">Default `true`</dd>
<dd>Whether Fluxer runs its own LiveKit voice server on this machine. Use `true` or `false`. The bundled LiveKit is the first server in the default voice region. With `false`, Fluxer creates the default region with no server in it, removes the server it made for the bundled LiveKit and keeps calls on the servers you add with `rexctl voice add`, `rexctl voice join` or the admin panel. rexctl also calls it `voice.bundled`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_default_region">
<dt>`FLUXER_LIVEKIT_DEFAULT_REGION`</dt>
<dd class="flx-setting-default">Default `{"id":"default","name":"Default","emoji":"🌍","latitude":0,"longitude":0}`</dd>
<dd>The voice region Fluxer creates when no voice regions exist yet, as a JSON object with `id`, `name`, `emoji`, `latitude` and `longitude`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_enabled">
<dt>`FLUXER_LIVEKIT_ENABLED`</dt>
<dd class="flx-setting-default">Default `true`</dd>
<dd>Whether voice and video calls are turned on. Use `true` or `false`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_internal_url">
<dt>`FLUXER_LIVEKIT_INTERNAL_URL`</dt>
<dd>The URL the API uses for the LiveKit control API of the bundled LiveKit, the first server in the default voice region. Servers added in the admin panel use their own address. Fluxer ignores it when `FLUXER_LIVEKIT_BUNDLED` is `false`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_node_ip">
<dt>`FLUXER_LIVEKIT_NODE_IP`</dt>
<dd>The public IP address voice and video use, when Fluxer can't find it by itself. Set `FLUXER_LIVEKIT_USE_EXTERNAL_IP` to `false` with it. rexctl also calls it `voice.public_ip`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_stun_primary">
<dt>`FLUXER_LIVEKIT_STUN_PRIMARY`</dt>
<dd class="flx-setting-default">Default `stun.l.google.com:19302`</dd>
<dd>The first STUN host LiveKit asks to find its public IP address, as `host:port`. Point it at another STUN host to avoid contacting Google.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_stun_secondary">
<dt>`FLUXER_LIVEKIT_STUN_SECONDARY`</dt>
<dd class="flx-setting-default">Default `stun1.l.google.com:19302`</dd>
<dd>The second STUN host LiveKit asks to find its public IP address, as `host:port`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_tcp_port">
<dt>`FLUXER_LIVEKIT_TCP_PORT`</dt>
<dd class="flx-setting-default">Default `7881`</dd>
<dd>The TCP port for voice and video. rexctl also calls it `voice.tcp_port`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_turn_servers">
<dt>`FLUXER_LIVEKIT_TURN_SERVERS`</dt>
<dd class="flx-setting-default">Default `[]`</dd>
<dd>TURN servers that browsers and apps get when they join a call, as a JSON array of objects with `host`, `port` and `protocol`, and either `username` and `credential` or `secret` with an optional `ttl`, such as `[{"host":"turn.example.com","port":3478,"protocol":"udp","secret":"a-long-random-secret"}]`. Use `udp`, `tcp` or `tls` for `protocol`, and a hostname or an IPv4 address for `host`. With `secret`, LiveKit makes short-lived credentials for each participant in the form coturn checks with `use-auth-secret`, and `ttl`, a whole number from 1, sets how many seconds they last. The bundled voice server and the servers you add with `rexctl voice add` give these to clients, and rexctl restarts the added servers one at a time when the list changes. A server that joined with `rexctl voice join` gets the list when it joins and on each `rexctl upgrade` in its voice folder, unless the instance runs an older release than the rexctl there. Set it when callers can't connect to a voice server directly, such as from networks that allow only port 443. When it's empty, clients get no TURN server. The API doesn't start with a value it can't read, and `rexctl config set` refuses such a value.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_udp_port">
<dt>`FLUXER_LIVEKIT_UDP_PORT`</dt>
<dd class="flx-setting-default">Default `7882`</dd>
<dd>The UDP port for voice and video. rexctl also calls it `voice.udp_port`.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_url">
<dt>`FLUXER_LIVEKIT_URL`</dt>
<dd>The URL browsers and apps use for voice signalling. When it's empty, Fluxer uses the public origin, or `FLUXER_PUBLIC_SCHEME`, `FLUXER_DOMAIN` and `FLUXER_PUBLIC_PORT`, followed by `/livekit`. Set it only when LiveKit runs on another host.</dd>
</div>
<div class="flx-setting" id="fluxer_livekit_use_external_ip">
<dt>`FLUXER_LIVEKIT_USE_EXTERNAL_IP`</dt>
<dd class="flx-setting-default">Default `true`</dd>
<dd>Whether LiveKit finds its public IP address through STUN. Use `true` or `false`. Set it to `false` when you set `FLUXER_LIVEKIT_NODE_IP`.</dd>
</div>
<div class="flx-setting" id="fluxer_voice_health_interval_ms">
<dt>`FLUXER_VOICE_HEALTH_INTERVAL_MS`</dt>
<dd>How often each API node checks every active voice server, in milliseconds. A server that fails two checks in a row gets no new calls until a check passes. Set it to `0` to turn the checks off. When it's empty, the API checks every 15 seconds.</dd>
</div>
<div class="flx-setting" id="fluxer_voice_join_allow_private_endpoints">
<dt>`FLUXER_VOICE_JOIN_ALLOW_PRIVATE_ENDPOINTS`</dt>
<dd>Whether the API accepts a voice server joining with an endpoint that resolves to a private address. Use `true` or `false`. Set it to `true` only for tests and private networks.</dd>
</div>
<div class="flx-setting" id="fluxer_voice_p2p_stun_urls">
<dt>`FLUXER_VOICE_P2P_STUN_URLS`</dt>

## Backups

Fluxer backs up its database before every upgrade. These add regular backups, which Fluxer keeps in the `backups` folder of its data folder. [Copy them off the machine](/operator/backups/#copy-backups-off-the-machine), because they are on the same disk as the instance.

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_backup_hour">
<dt>`FLUXER_BACKUP_HOUR`</dt>
<dd class="flx-setting-default">Default `3`</dd>
<dd>The hour of the day, from 0 to 23, when Fluxer takes its own scheduled backup. It's in UTC inside a container unless the container has TZ set, and in the machine's time zone otherwise. When it's empty, Fluxer uses 3.</dd>
</div>
<div class="flx-setting" id="fluxer_backup_keep">
<dt>`FLUXER_BACKUP_KEEP`</dt>
<dd class="flx-setting-default">Default `7`</dd>
<dd>How many of its own scheduled backups Fluxer keeps. When it's empty, Fluxer keeps 7.</dd>
</div>
<div class="flx-setting" id="fluxer_backup_on_upgrade">
<dt>`FLUXER_BACKUP_ON_UPGRADE`</dt>
<dd class="flx-setting-default">Default `true`</dd>
<dd>Set to `false` to stop Fluxer backing up its database by itself before it starts on a newer release. When it's empty, it backs up and keeps the newest 3 of these backups. rexctl backs up before every upgrade and sets this to `false`.</dd>
</div>
<div class="flx-setting" id="fluxer_backup_schedule">
<dt>`FLUXER_BACKUP_SCHEDULE`</dt>
<dd class="flx-setting-default">Default `off`</dd>
<dd>How often Fluxer backs itself up into its own data folder, as `daily`, `weekly` or `off`. Fluxer shows a maintenance page while it copies uploads and the search index. On Linux, `rexctl backup schedule` uses a timer on the machine instead, and it sets this one only where the machine has no timer, such as Docker Desktop. `rexctl backup list` copies these backups into rexctl's backup folder, from Fluxer's volume for a container and from Fluxer's data folder for systemd.</dd>
</div>
</dl>

## Updates

Fluxer doesn't look for new releases by itself until you turn the check on. Then it checks once a day and shows a newer release in the admin panel, the log and `fluxerd version`. The request [holds no instance ID, domain, version, counts or cookies](/operator/upgrades/#turning-the-check-on).

<dl class="flx-settings">
<div class="flx-setting" id="fluxer_install_method">
<dt>`FLUXER_INSTALL_METHOD`</dt>
<dd>How this instance was installed, which picks the upgrade command Fluxer shows and the command the setup wizard gives for the setup token. Use `compose`, `docker`, `helm`, `systemd` or `rexctl`. The release's `compose.yaml` sets `compose`, the `docker run` line in the Docker guide `docker`, the Helm chart `helm` and rexctl `rexctl`. When it's empty, Fluxer in Docker or Podman shows steps that fit any way of running the image. Set it when the admin panel shows steps that don't fit, such as `compose` for a `compose.yaml` from an older release or `docker` for a `docker run` line without it.</dd>
</div>
<div class="flx-setting" id="fluxer_update_check">
<dt>`FLUXER_UPDATE_CHECK`</dt>
<dd class="flx-setting-default">Default `false`</dd>
<dd>Set to `true` to have Fluxer ask `https://fluxer.dev/releases.json` once a day whether a newer release is out, and show newer releases in the admin panel and the log. The request is plain and holds nothing about your instance. It's off unless you set it.</dd>
</div>
<div class="flx-setting" id="fluxer_update_check_url">
<dt>`FLUXER_UPDATE_CHECK_URL`</dt>
<dd>Where Fluxer asks for the list of releases. When it's empty, it asks `https://fluxer.dev/releases.json`. Any other server you set here must send JSON in the same format as that list.</dd>
</div>
<div class="flx-setting" id="fluxer_upgrade_command">
<dt>`FLUXER_UPGRADE_COMMAND`</dt>
<dd>The upgrade command Fluxer shows when a newer release is out, with `{version}` where the version goes. The Helm chart and rexctl set it. Set it yourself when you upgrade some other way, such as with Quadlet or Ansible.</dd>
</div>
</dl>

</div>
<div class="flx-setting" id="fluxer_postgres_username">
<dt>`FLUXER_POSTGRES_USERNAME`</dt>

<dt>`FLUXER_API_MAX_CONCURRENT_FORM_UPLOADS`</dt>
<dd>How many attachment files sent as multipart form data the API streams to the object store at once, from 1 to 10000. Each one can use up to about 25 MiB of memory. A file that waits more than 10 seconds for a turn gets 503 with a Retry-After header. When it's empty, the API uses `16`.</dd>
</div>
<div class="flx-setting" id="fluxer_api_max_inflight_requests">
<dt>`FLUXER_API_MAX_INFLIGHT_REQUESTS`</dt>
<dd>How many requests the API handles at once before it responds to new ones with 503 and a Retry-After header, from 1 to 100000. When it's empty, the API uses `512`.</dd>
</div>
<div class="flx-setting" id="fluxer_api_request_timeout_ms">
<dt>`FLUXER_API_REQUEST_TIMEOUT_MS`</dt>
<dd>How long a client may take over a whole request to the API, in milliseconds from 1000 to 3600000. Raise it for large uploads or slow links. When it's empty, the API uses `120000`.</dd>
</div>
<div class="flx-setting" id="fluxer_api_trusted_callers">
<dt>`FLUXER_API_TRUSTED_CALLERS`</dt>
<dd>A JSON array of trusted callers, such as a front end that calls the API for its own visitors. Each entry is an object with a `name`, a `key` of at least 32 characters and `buckets`, a non-empty list of the rate limit buckets the caller may pass a client address for. The caller sends its key in the `X-Fluxer-Internal-Key` header and the client address in the `X-Fluxer-Client-IP` header. Keep it secret.</dd>
</div>
<div class="flx-setting" id="fluxer_api_worker_lane_concurrency_overrides">
<dt>`FLUXER_API_WORKER_LANE_CONCURRENCY_OVERRIDES`</dt>
<dd>How many jobs each worker lane runs at once, as a JSON object that maps each lane to a whole number of at least 1. The lanes are `realtime`, `unfurl`, `lifecycle`, `batch` and `crosspost`. Lanes left out use 10, 20, 8, 12 and 8 in that order, scaled down on any machine with fewer than 4 CPU cores.</dd>
</div>
<div class="flx-setting" id="fluxer_client_ip_header_name">
<dt>`FLUXER_CLIENT_IP_HEADER_NAME`</dt>
<dd>The request header that has the client's IP address. When it's empty, the api, worker, admin and gateway services and the push relay use `x-forwarded-for`, the header the edge sets.</dd>

<div class="flx-setting" id="fluxer_ip_ban_refresh_interval_ms">
<dt>`FLUXER_IP_BAN_REFRESH_INTERVAL_MS`</dt>
<dd>How often the API reloads its IP ban list, in milliseconds. When it's empty, the API uses `300000`. A value of `0` turns the periodic reload off.</dd>
</div>
<div class="flx-setting" id="fluxer_trust_client_ip_header">
<dt>`FLUXER_TRUST_CLIENT_IP_HEADER`</dt>
<dd class="flx-setting-default">Default `true`</dd>
<dd>Whether Fluxer trusts the client address in the `FLUXER_CLIENT_IP_HEADER_NAME` header. Use `true` or `false`. The api, worker, admin and gateway services and the push relay use it. With `false`, they use the address of the connection, which behind the edge is the edge itself.</dd>
</div>
</dl>

<dd>PostgreSQL `max_parallel_workers_per_gather`, how many parallel workers one step of a query can use.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_max_wal_size">
<dt>`FLUXER_POSTGRES_MAX_WAL_SIZE`</dt>
<dd class="flx-setting-default">Default `2GB`</dd>
<dd>PostgreSQL `max_wal_size`, how large the write-ahead log may grow before PostgreSQL starts a checkpoint.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_min_wal_size">
<dt>`FLUXER_POSTGRES_MIN_WAL_SIZE`</dt>
<dd class="flx-setting-default">Default `80MB`</dd>
<dd>PostgreSQL `min_wal_size`, the write-ahead log space PostgreSQL keeps for reuse after a checkpoint.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_random_page_cost">
<dt>`FLUXER_POSTGRES_RANDOM_PAGE_COST`</dt>
<dd class="flx-setting-default">Default `1.1`</dd>
<dd>PostgreSQL `random_page_cost`, how costly the query planner thinks fetching a random disk page is next to a sequential one. Values near 1 suit SSDs.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_server_max_connections">
<dt>`FLUXER_POSTGRES_SERVER_MAX_CONNECTIONS`</dt>
<dd class="flx-setting-default">Default `150`</dd>
<dd>PostgreSQL `max_connections`, how many connections the database accepts in total. Keep it above the sum of all pool sizes, counting each worker replica.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_shared_buffers">
<dt>`FLUXER_POSTGRES_SHARED_BUFFERS`</dt>
<dd class="flx-setting-default">Default `192MB`</dd>
<dd>PostgreSQL `shared_buffers`, the memory PostgreSQL uses for its own cache.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_shared_preload_libraries">
<dt>`FLUXER_POSTGRES_SHARED_PRELOAD_LIBRARIES`</dt>
<dd class="flx-setting-default">Default `pg_stat_statements`</dd>
<dd>PostgreSQL `shared_preload_libraries`, the extensions PostgreSQL loads at start, separated by commas. Keep `pg_stat_statements` in the list. The api turns it on at start.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_track_io_timing">
<dt>`FLUXER_POSTGRES_TRACK_IO_TIMING`</dt>
<dd class="flx-setting-default">Default `on`</dd>
<dd>PostgreSQL `track_io_timing`, whether PostgreSQL times its disk I/O for its statistics. Use `on` or `off`.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_wal_buffers">
<dt>`FLUXER_POSTGRES_WAL_BUFFERS`</dt>
<dd class="flx-setting-default">Default `16MB`</dd>
<dd>PostgreSQL `wal_buffers`, the memory for write-ahead log data not yet written to disk.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_wal_compression">
<dt>`FLUXER_POSTGRES_WAL_COMPRESSION`</dt>
<dd class="flx-setting-default">Default `zstd`</dd>
<dd>PostgreSQL `wal_compression`, how full-page images in the write-ahead log are compressed, such as `lz4`, `pglz` or `off`. PostgreSQL 14 takes only `on` or `off`, and there Fluxer uses `on` unless you set it.</dd>
</div>
<div class="flx-setting" id="fluxer_postgres_work_mem">
<dt>`FLUXER_POSTGRES_WORK_MEM`</dt>
<dd class="flx-setting-default">Default `4MB`</dd>
<dd>PostgreSQL `work_mem`, the memory each sort or hash step in a query can use before it spills to disk.</dd>
</div>
<div class="flx-setting" id="fluxer_rust_process">
<dt>`FLUXER_RUST_PROCESS`</dt>
<dd>How the Rust services run. `single` runs snowflakes, users, messages, gifs, unfurl, push, app-proxy and admin in one process, and `per-service` runs one process for each. When it's empty, a new instance picks `single` on its first start and keeps it. An older instance with no choice saved uses `per-service`. rexctl also calls it `rust.process`.</dd>
</div>
<div class="flx-setting" id="fluxer_rust_server_tokio_worker_threads">
<dt>`FLUXER_RUST_SERVER_TOKIO_WORKER_THREADS`</dt>
<dd>How many worker threads the async runtime uses when `FLUXER_RUST_PROCESS` is `single`, set as `TOKIO_WORKER_THREADS` of the one Rust process. Fluxer sizes it from the CPUs it can use.</dd>
</div>
<div class="flx-setting" id="fluxer_tokio_worker_threads">
<dt>`FLUXER_TOKIO_WORKER_THREADS`</dt>
<dd>How many worker threads the async runtime uses in the app-proxy, push, admin, snowflakes, users, gifs, messages and unfurl services, set as their `TOKIO_WORKER_THREADS`. Fluxer sizes it from the CPUs it can use.</dd>
</div>
<div class="flx-setting" id="fluxer_users_postgres_max_connections">
<dt>`FLUXER_USERS_POSTGRES_MAX_CONNECTIONS`</dt>
<dd class="flx-setting-default">Default `4`</dd>
<dd>The size of the PostgreSQL connection pool of the users service.</dd>
</div>
</dl>

<dd>The share of deleted space in a volume that makes SeaweedFS compact it, as a fraction, set as its `-master.garbageThreshold`.</dd>

<dd class="flx-setting-default">Default `380MiB`</dd>
<dd>The soft memory limit of the Go runtime in SeaweedFS, set as its `GOMEMLIMIT`. Go can't see how much memory the other parts use, so keep it well below the memory of the machine.</dd>

<div class="flx-setting" id="fluxer_seaweedfs_init_attempts">

<dt>`FLUXER_SEAWEEDFS_S3_CONCURRENT_UPLOADS`</dt>
<dd class="flx-setting-default">Default `5`</dd>
<dd>How many uploads the bundled object store writes at once, set as its `-s3.concurrentFileUploadLimit`. More uploads wait for a free slot. Each upload in progress uses up to 32 MB of memory in SeaweedFS.</dd>
</div>
<div class="flx-setting" id="fluxer_seaweedfs_telemetry">
<dt>`FLUXER_SEAWEEDFS_TELEMETRY`</dt>
<dd class="flx-setting-default">Default `false`</dd>
<dd>Whether SeaweedFS sends usage data to the SeaweedFS project, set as its `-master.telemetry`. Use `true` or `false`.</dd>
</div>
<div class="flx-setting" id="fluxer_seaweedfs_uploads_ttl">
<dt>`FLUXER_SEAWEEDFS_UPLOADS_TTL`</dt>
<dd class="flx-setting-default">Default `1d`</dd>
<dd>How long the bundled object store keeps files in the uploads bucket before it deletes them, such as `1d` or `12h`. Use `off` to keep them. A new value applies to uploads written after the next start, and files already stored keep their old expiry.</dd>
</div>

</div>
<div class="flx-setting" id="fluxer_seaweedfs_volume_max">
<dt>`FLUXER_SEAWEEDFS_VOLUME_MAX`</dt>
<dd class="flx-setting-default">Default `10000`</dd>
<dd>The most volumes the SeaweedFS volume store may have, set as its `-volume.max`.</dd>
</div>
<div class="flx-setting" id="fluxer_seaweedfs_volume_size_limit_mb">
<dt>`FLUXER_SEAWEEDFS_VOLUME_SIZE_LIMIT_MB`</dt>

<dd>The size in MB a volume can grow to before SeaweedFS stops writing to it, set as its `-master.volumeSizeLimitMB`.</dd>
</div>

<dt>`FLUXER_VALKEY_APPENDFSYNC`</dt>
<dd class="flx-setting-default">Default `everysec`</dd>
<dd>Valkey `appendfsync`, how often Valkey flushes its append-only file to disk. Use `always`, `everysec` or `no`. With `everysec`, a crash can lose the last second of writes.</dd>

<div class="flx-setting" id="fluxer_valkey_maxmemory">
<dt>`FLUXER_VALKEY_MAXMEMORY`</dt>
<dd class="flx-setting-default">Default `128mb`</dd>
<dd>Valkey `maxmemory`, the most memory Valkey may use for stored data. The append-only file buffer and memory fragmentation come on top.</dd>

<dd>Valkey `maxmemory-policy`, what Valkey does when its data grows to `FLUXER_VALKEY_MAXMEMORY`. With `noeviction`, writes fail when Valkey is full and no data is dropped.</dd>

<div class="flx-setting" id="fluxer_valkey_save">

## Values from files

Every setting also takes its value from a file, such as a Docker or Kubernetes secret.

1. Set `NAME_FILE` to the path of the file.
2. Leave `NAME` unset. Fluxer refuses to start when both have a value.
3. Let the account Fluxer runs as read the file.
