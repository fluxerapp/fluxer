The Admin API lets you manage accounts, guilds, messages and configuration on your instance. Every route is under `/v1/admin` and uses the same JSON format and [error response](#error-response) as the [HTTP API](/http-api/). It has its own [credentials](#authentication), [ACLs](#acl-evaluation) and rate limits.

## Authentication

Send one of these credentials in the `Authorization` header. [Authentication](/authentication/) has the token formats.

| Credential | Header value |
| --- | --- |
| User session token | The token with no prefix |
| Admin OAuth2 access token | `Bearer` and the token, issued by the built-in Admin OAuth2 application |
| Admin API key | `Admin` and the token |

The account needs `admin:authenticate` or `*`. The API refuses bot tokens and access tokens from any other OAuth2 application. No Admin route needs an OAuth2 scope, MFA or sudo mode.

An [Admin API key](/admin-api/api-keys/) acts as the account that created it and only works on paths under `/v1/admin`. A request made with a key needs one of the route's ACLs on the key and one on the account that owns it, unless that account has `*`. Removing an ACL from the key or its owner takes effect on the next request.

## ACL evaluation

Each route needs one or more ACLs, and the caller needs at least one of them. The wildcard `*` satisfies every ACL, including ones added later. Some routes need extra ACLs depending on the request, such as `user:view:email` on [List users](/admin-api/users/#list-users) when you filter by email, and you need every one of those.

[Update guild](/admin-api/guilds/#update-guild) and [Queue bulk job](/admin-api/bulk-jobs/#queue-bulk-job) need a different ACL depending on what the request body changes.

[Set user ACLs](/admin-api/users/#set-user-acls), [Create Admin API key](/admin-api/api-keys/#create-admin-api-key) and [Update Admin API key](/admin-api/api-keys/#update-admin-api-key) only accept values from the [ACL registry](#acl-registry). You can only grant ACLs you have yourself, and trying to grant any other ACL returns 403 `MISSING_ACL`. An account with `*` can grant any ACL.

## Admin audit entry object

An Admin audit entry records one Admin action against one target. Almost every Admin route records an entry, reads included. A request refused by authentication, ACLs, rate limits or validation records nothing.

Read entries store IDs, filters and counts, never query text, email addresses, IP addresses or other free-form input.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| log_id | snowflake | The ID of the audit entry |
| admin_user_id | snowflake | The ID of the acting account, or `0` for an action run with rexctl |
| admin_user | ?[Admin user summary](#admin-user-summary-object) object | The acting account, or null when it no longer exists |
| target_type | string | The [audit target type](#audit-target-types) (1-256 characters) |
| target_id | string | The target ID as a decimal string, or `0` when the target has no snowflake |
| target_user | ?[Admin user summary](#admin-user-summary-object) object | The target account, or null when the target is not an account |
| target_guild | ?[Admin guild summary](#admin-guild-summary-object) object | The target guild, or null when the target is not a guild |
| target_channel | ?[Admin channel summary](#admin-channel-summary-object) object | The target channel or the channel in `channel_id` metadata, or null |
| related_users | map[snowflake, [Admin user summary](#admin-user-summary-object) object] | The accounts the entry references, keyed by ID |
| related_guilds | map[snowflake, [Admin guild summary](#admin-guild-summary-object) object] | The guilds the entry references, keyed by ID |
| related_channels | map[snowflake, [Admin channel summary](#admin-channel-summary-object) object] | The channels the entry references, keyed by ID |
| action | string | The [audit action](#audit-actions) (1-256 characters) |
| access | string | `read` or `write` |
| audit_log_reason | ?string | The [audit reason](#audit-reasons), or null |
| metadata | map[string, string] | The extra values the route recorded |
| created_at | ISO8601 timestamp | When the entry was recorded |

When an Admin API key made the request, `metadata.via` is `api_key:` followed by the key ID. When rexctl made it, `metadata.via` is `rexctl`, and `metadata.host_user` is set when rexctl knows who ran it.

```json
    "username": "operator",
    "discriminator": "0042",
    "global_name": "Operator"
  },
  "target_type": "user",
  "target_id": "1493004551122763776",
  "target_user": {
    "id": "1493004551122763776",
    "username": "subject",
    "discriminator": "0007",
    "global_name": null
  },
  "target_guild": null,

  "related_users": {},

  },

}
```

## Audit reasons

Send `X-Audit-Log-Reason` on any route marked Audit reason, and the API stores it in `audit_log_reason` on each entry the request records. The API trims the value and strips control characters. A blank value or one longer than 512 characters is dropped without failing the request. Routes that require a reason, such as the [enforcement](/admin-api/enforcement/) routes, return 400 when the value is missing or dropped. Send the value as plain UTF-8, because the API doesn't percent-decode it.

## Errors and rate limits

### Error response

An Admin error uses the same format as the [HTTP API error response](/http-api/#error-response).

These errors can come from any Admin route.

| Status | Body | Condition |
| --- | --- | --- |
| 400 | [error response](#error-response) | `INVALID_FORM_BODY` when the path, query or body is invalid |
| 401 | [error response](#error-response) | `UNAUTHORIZED` when the credential is missing, invalid or a bot token |
| 403 | [error response](#error-response) | `ACCESS_DENIED` for an access token from an OAuth2 application other than Admin |
| 403 | [error response](#error-response) | `MISSING_PERMISSIONS` when the account holds neither `admin:authenticate` nor `*` |
| 403 | [error response](#error-response) | `MISSING_ACL` when the caller holds none of the route's ACLs |
| 429 | [error response](#error-response) | `RATE_LIMITED` when a rate limit is hit |

Admin rate limits count each account and credential type separately, and an Admin API key never shares its owner's session limits. See [Rate limits](/topics/rate-limits/) for the headers and the global limit.

## List audit log entries

<RouteHeader method="GET" path="/v1/admin/audit-logs" auditReason />

Returns a page of [Admin audit entries](#admin-audit-entry-object), newest first by default. You need `audit_log:view`.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| q? | string | Search `action`, `target_type`, `target_id` and `audit_log_reason` (1-1,024 characters) |
| admin_user_id? | snowflake | Only entries by this acting account |
| target_type? | string | Only entries with this [target type](#audit-target-types) (1-64 characters) |
| target_id? | string | Only entries with this target ID |
| access? | string | `read` or `write` |
| sort_by? | string | `createdAt` or `relevance`, used only with `q` (default `createdAt`) |
| sort_order? | string | `asc` or `desc`, used only with `q` (default `desc`) |
| limit? | integer | The maximum number of entries to return (1-200, default 50) |
| offset? | integer | The number of entries to skip (default 0) |

Without a search index, the API ignores `q` and only filters the newest `limit` plus `offset` entries, so a page and `total` can come back short.

### Response body

| Field | Type | Description |
| --- | --- | --- |
| logs | array[[Admin audit entry](#admin-audit-entry-object) object] | The entries in this page |
| total | integer | The number of entries that match |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | response body | The page was returned |

Records a `search_audit_logs` audit entry when `q` is set and `list_audit_logs` otherwise, without the query text.

The rate limit is 100 requests per minute, on the `admin:audit_log` bucket.
