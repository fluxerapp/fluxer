A voice region is a group of LiveKit servers, and Fluxer places each new [voice](/voice/) session in a region and then on a server inside it. Each API node reloads the configuration shortly after a write, and a write never moves or disconnects a session that is already connected.

## Placement eligibility

Regions and servers have the same eligibility fields, and a session can use a server only when it is active and both the server and its region admit the session.

| Field | Rule |
| --- | --- |
| allowed_user_ids | When the list is not empty, only the accounts in it are admitted |
| allowed_guild_ids | Admits only these guilds, or lets them skip `vip_only` and `required_guild_features` when those are set |
| vip_only | The guild needs the `VIP_VOICE` [guild feature](/http-api/guilds/#guild-features) |
| required_guild_features | The guild needs at least one of the listed features |

When `allowed_guild_ids`, `vip_only` or `required_guild_features` is set, calls in direct messages and group direct messages can't use that region or server.

## Admin voice region object

You pick the `id` when you create the region, and you can't change it later. A channel's `rtc_region` is this ID.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| id | string | The ID of the region (1-64 characters) |
| name | string | The name shown for the region in a client (1-100 characters) |
| emoji | string | The emoji shown for the region (1-64 characters) |
| latitude | number | The latitude placement measures distance from |
| longitude | number | The longitude placement measures distance from |
| is_default<sup>1</sup> | boolean | Whether automatic placement falls back to this region |
| vip_only | boolean | Whether the guild needs `VIP_VOICE` |
| required_guild_features | array[string] | [Guild features](/http-api/guilds/#guild-features) that admit a guild (max 100) |
| allowed_guild_ids | array[snowflake] | The guilds admitted without other guild checks (max 1000) |
| allowed_user_ids | array[snowflake] | The only accounts allowed to use the region, when not empty (max 1000) |
| created_at | ?ISO8601 timestamp | When the region was created |
| updated_at | ?ISO8601 timestamp | When the region last changed |
| servers? | array[[Admin voice server](#admin-voice-server-object) object] | The servers in the region, when `include_servers` is true |

<sup>1</sup> To change the default, turn the flag off on the old default region too.

## Admin voice server object

A voice server is one LiveKit deployment in one region, identified by its `region_id` and `server_id`. To move a server to another region, delete it and create it again. You send `api_key` and `api_secret` when you create or update a server, and no read returns them.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| region_id | string | The ID of the region the server belongs to (1-64 characters) |
| server_id | string | The ID of the server, unique inside its region (1-64 characters) |
| endpoint | string | The LiveKit `ws://` or `wss://` URL that clients connect to |
| latitude | ?number | The latitude used for this server, or null to use the region's |
| longitude | ?number | The longitude used for this server, or null to use the region's |
| is_active | boolean | Whether new sessions can be placed on the server |
| soft_connection_limit | ?integer | See [soft connection limits](#soft-connection-limits), or null for none (1-2147483647) |
| notes | ?string | Admin notes about the server, or null for none |
| vip_only | boolean | Whether the guild needs `VIP_VOICE` |
| required_guild_features | array[string] | [Guild features](/http-api/guilds/#guild-features) that admit a guild (max 100) |
| allowed_guild_ids | array[snowflake] | The guilds admitted without other guild checks (max 1000) |
| allowed_user_ids | array[snowflake] | The only accounts allowed to use the server, when not empty (max 1000) |
| internal_endpoint | ?string | The `http://` or `https://` URL the API uses for the LiveKit control API and health checks, or null to use `endpoint` |
| draining | boolean | Whether new calls go to other servers while calls already on this one keep going |
| public_ipv4 | ?string | The public IPv4 address LiveKit gives to clients, or null when none is known |
| public_ipv6 | ?string | The public IPv6 address LiveKit gives to clients, or null when none is known |
| health | [health](#voice-server-health-object) object | The server's health as the API node that answered last saw it |
| duplicate_api_key | boolean | Whether another server uses the same `api_key` |
| created_at | ?ISO8601 timestamp | When the server was created |
| updated_at | ?ISO8601 timestamp | When the server last changed |

### Voice server health object

| Field | Type | Description |
| --- | --- | --- |
| status | string | `up`, `down`, or `unknown` before the first check |
| checked_at | ?ISO8601 timestamp | When the last check ran, or null before the first |
| error | ?string | The status code or short transport error of the last failed check |

Every API node checks every active server every `FLUXER_VOICE_HEALTH_INTERVAL_MS`, 15 seconds by default, with `GET` on `internal_endpoint` or `endpoint`. Two failed checks in a row mark a server down, and one passing check marks it up. Placement sends no new calls to a server that is down, unless every server it could pick is down. A call pinned to a server that is down moves on its next join. A check of a public endpoint that resolves to a private address doesn't run, and the status stays `unknown`.

## Draining

A server with `draining` set gets no new calls. Calls already on it keep going, and people who join those calls still land on it. `rexctl` sets it while it upgrades or removes a server. Unlike `is_active` false, draining never splits a call in two.

## Soft connection limits

`soft_connection_limit` is the connection count at which placement starts to prefer the region's other servers, and it never refuses a session. The count comes from [Get voice state counts](/admin-api/gateway/#get-voice-state-counts). Each API node refreshes it every 15 seconds, and a burst of joins between refreshes can go past the limit. The limit is checked when a channel's first session is placed, and later joins to that channel use the same server.

## Voice join tokens

A join token lets one machine register one voice server with [Join a voice server](#join-a-voice-server). It looks like `fvj_` followed by its ID, an underscore and a 43 character secret. Fluxer stores only a hash of the secret. A token works once, for 60 seconds to 24 hours, and the list keeps it for 7 days after it expires. Whoever runs the server can record the calls placed on it. A token trusts that machine with calls, and it gives no other access.

## Join a voice server

These routes are for the voice machine, not for admins. They take `Authorization: VoiceJoin` followed by a join token, and the rate limit is 10 requests per minute for each address.

<RouteHeader method="POST" path="/v1/voice/join/preview" unauthenticated />

Shows what a join would choose, without using the token. The JSON body has `public_ipv4`, `public_ipv6`, `region_id`, `cpu_count`, `memory_bytes` and `rexctl_version`, all optional. Fluxer looks up one address in GeoIP, the first of `public_ipv4`, `public_ipv6` and the address the request comes from. The response has the suggested `server_id`, `server_id_pinned` set to true when the token sets the server ID, the `region` with its `id`, `name`, `distance_km`, whether it's `new` and its `source`, the `latitude` and `longitude` from GeoIP rounded to 0.1 degrees, the `hostname` preset, a `suggested_hostname`, the `soft_connection_limit` preset, the `webhook_url`, the `api_code_version`, the `release` of the API, `expires_at` and the instance's `turn_servers`.

Fluxer picks the token's region first, then an existing region in `region_id`, then the existing region nearest to the machine when the instance has a GeoIP database, and the default region otherwise. It never creates a region unless the token has a new one. The `source` says which of these it used, as `token`, `requested`, `nearest` or `default`.

<RouteHeader method="POST" path="/v1/voice/join" unauthenticated />

Registers the server and uses the token.

| Field | Type | Description |
| --- | --- | --- |
| endpoint | string | The public `wss://` URL of the server. A host that is an IP address must be IPv4. A server with only IPv6 needs a hostname |
| api_key | string | A LiveKit API key no other server uses (1-256 characters) |
| api_secret | string | Its secret (32-256 characters) |
| server_id? | string | The server ID, ignored when the token has one |
| region_id? | string | An existing region, ignored when the token has one |
| latitude?<sup>1</sup> | number | The server's latitude |
| longitude?<sup>1</sup> | number | The server's longitude |
| soft_connection_limit? | integer | Ignored when the token has one |
| public_ipv4? | string | The machine's public IPv4 address, for GeoIP and the admin panel |
| public_ipv6? | string | The machine's public IPv6 address, for GeoIP and the admin panel |

<sup>1</sup> Send both coordinates or neither

Fluxer resolves the endpoint's host, refuses it when any address is private unless `FLUXER_VOICE_JOIN_ALLOW_PRIVATE_ENDPOINTS` is true, and connects to the addresses it checked, one after another until one answers. `GET` on the endpoint's path must answer `OK` within 10 seconds with a certificate Fluxer trusts, and the room service must accept the key and secret. Then Fluxer saves the server, active and not draining, and the token stops working. The response has `server_id`, `region_id`, `endpoint`, `webhook_url`, `node_url` and `turn_servers`.

`turn_servers` is the list in `FLUXER_LIVEKIT_TURN_SERVERS` on the instance, as objects with `host`, `port`, `protocol` and either `username` and `credential` or `secret` and `ttl`. It's empty when the setting is. rexctl puts it in the LiveKit configuration of the server.

| Status | Code | Condition |
| --- | --- | --- |
| 400 | `VOICE_JOIN_ENDPOINT_INVALID` | The endpoint isn't `wss://`, uses an IPv6 address, a private address or another hostname than the token's |
| 400 | `VOICE_JOIN_ENDPOINT_UNREACHABLE` | The endpoint didn't answer `OK`, with the status or error in `detail` |
| 400 | `VOICE_JOIN_KEY_MISMATCH` | The server refused the key and secret |
| 401 | `VOICE_JOIN_TOKEN_INVALID` | The token is unknown, used, expired or revoked |
| 404 | `UNKNOWN_VOICE_REGION` | No region has the ID in `region_id` |
| 409 | `VOICE_JOIN_TOKEN_BUSY` | Another join with the token is running |
| 409 | `VOICE_SERVER_ID_IN_USE` | Another server has the ID |
| 409 | `VOICE_SERVER_API_KEY_IN_USE` | Another server uses the key |

A failed join leaves the token unused. The same machine can try again.

## Voice node routes

A server that joined manages its own row with `GET`, `PATCH` and `DELETE` on `/v1/voice/node`. The request takes `Authorization: Bearer` followed by an HS256 JWT signed with the server's API secret, with these claims:

- `iss` set to the server's API key.
- `aud` set to `fluxer-voice-node`.
- `method` and `path` of the request, with `path` set to `/voice/node`.
- `exp` in the future and at most 5 minutes ahead, and `iat` when present. Fluxer allows 60 seconds of clock difference either way.
- `sha256` set to the base64 SHA-256 of the body, or an empty string for `GET` and `DELETE`.

Fluxer refuses tokens with a `video` grant. LiveKit participant tokens and webhooks signed with the same secret don't work here.

<RouteHeader method="GET" path="/v1/voice/node" unauthenticated />

Returns the server's `region_id`, `server_id`, `endpoint`, `latitude`, `longitude`, `is_active`, `draining`, `soft_connection_limit`, `public_ipv4`, `public_ipv6`, `turn_servers`, `features` and `health`. `features` lists what the API supports for voice servers. `server_addresses` means `PATCH` takes `public_ipv4` and `public_ipv6`.

<RouteHeader method="PATCH" path="/v1/voice/node" unauthenticated />

Takes `endpoint`, `draining`, `latitude`, `longitude`, `soft_connection_limit`, `public_ipv4` and `public_ipv6`, and returns the server like `GET`. An empty string for `public_ipv4` or `public_ipv6` clears it. Fluxer checks a new endpoint the same way as a join. When the server has an internal endpoint, Fluxer also tries the new public endpoint and logs a warning when it doesn't answer, without refusing the change. A new endpoint must keep the token's hostname, and a server can't change a soft connection limit the token set. A server can't change its region, its restrictions, `internal_endpoint` or `is_active`. A server an admin turned off stays off.

<RouteHeader method="DELETE" path="/v1/voice/node" unauthenticated />

Removes the server and answers 204.

Every node route can fail with these errors.

| Status | Code | Condition |
| --- | --- | --- |
| 401 | `VOICE_NODE_UNKNOWN` | No server has the key in `iss`, usually because an admin deleted it |
| 401 | `VOICE_NODE_SIGNATURE_INVALID` | The signature or a claim is wrong, or an admin changed the server's secret |
| 401 | `VOICE_NODE_TOKEN_EXPIRED` | The signature matches, and `exp` or `iat` is outside the allowed time. The clock of the voice machine is usually off |
