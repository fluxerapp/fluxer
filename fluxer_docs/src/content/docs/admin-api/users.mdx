These routes read and change any account on the instance. Each field group has its own route and [ACL](/admin-api/#acl-registry), and every route except [Get current Admin user](#get-current-admin-user) records an [Admin audit entry](/admin-api/#admin-audit-entry-object), reads included.

On an instance where members sign in with a username, the email routes return 400 `EMAIL_UNAVAILABLE_ON_INSTANCE` and you reset a password with [Create password reset link](#create-password-reset-link), which also works on an email instance that doesn't send email. On routes that record an [enforcement decision](/admin-api/enforcement/), the `X-Audit-Log-Reason` header is required and becomes the decision's first note. Blocking a user's avatar is on [Blocklists](/admin-api/blocklists/#block-a-users-current-avatar).

## Admin user object

The full admin view of one account, with the flags, lifecycle, contact and network fields the public [user object](/http-api/users/#user-object) leaves out. Without `user:view:email`, `user:view:dob` or `user:view:ip`, the fields that ACL protects are null (or false for the email booleans) and the request still succeeds.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| id | snowflake | The ID of the account |
| username | string | The username (1-32 characters) |
| discriminator<sup>1</sup> | integer | The discriminator from 0 to 9999, unpadded |
| global_name | ?string | The display name |
| bot | boolean | Whether the account is a bot |
| system | boolean | Whether the account is an official system account |
| flags | string | [Account flags](#account-flags) as a decimal string |
| premium_flags | integer | [Premium flags](#premium-flags) |
| avatar | ?string | The avatar hash |
| banner | ?string | The profile banner hash |
| bio | ?string | The profile bio |
| pronouns | ?string | The profile pronouns |
| accent_color | ?integer | The profile accent color |
| email<sup>2</sup> | ?string | The email address |
| email_verified<sup>2</sup> | boolean | Whether the email address is verified |
| email_bounced<sup>2</sup> | boolean | Whether mail to the address hard bounced |
| date_of_birth<sup>3</sup> | ?string | The date of birth as `YYYY-MM-DD` |
| locale | ?string | The saved [locale](/topics/locales/#supported-locales) |
| premium_type | ?integer | [Premium type](#premium-types) |
| premium_since | ?ISO8601 timestamp | When premium started |
| premium_until | ?ISO8601 timestamp | When premium ends |
| premium_grace_ends_at | ?ISO8601 timestamp | When the payment grace period ends |
| premium_lifetime_sequence | ?integer | The sequence number of the lifetime purchase |
| profile_badges | array[[Admin profile badge](#admin-profile-badge-object) object] | Every badge the account qualifies for, including hidden ones |
| temp_banned_until | ?ISO8601 timestamp | When the current suspension ends, or null when none is in force |
| pending_deletion_at | ?ISO8601 timestamp | When the scheduled deletion runs |
| pending_bulk_message_deletion_at | ?ISO8601 timestamp | When the account holder's own scheduled message deletion runs |
| deletion_reason_code | ?integer | [Deletion reason](#deletion-reasons) |
| deletion_public_reason | ?string | The reason shown to the account holder, set only on older deletions |
| deletion_audit_log_reason | ?string | The private deletion reason, null without `audit_log:view` |
| deletion_scheduled_by | ?snowflake | The ID of the account that scheduled the deletion |
| deletion_scheduled_at | ?ISO8601 timestamp | When the deletion was scheduled |
| enforcement_decision_id | ?snowflake | The [enforcement decision](/admin-api/enforcement/) that owns the account's state |
| acls | array[string] | The [Admin ACLs](/admin-api/#acl-registry) set on the account |
| traits | array[string] | The operator labels on the account, sorted (at most 100) |
| badge_ids | array[snowflake] | The [custom badges](/admin-api/badges/) given to the account (at most 10) |
| has_totp | boolean | Whether a TOTP authenticator is registered |
| has_password | boolean | Whether the account has a password |
| claimed | boolean | Whether the account can sign in from another device |
| account_tier | string | The [account tier](/http-api/users/#account-tiers) |
| date_of_birth_required | boolean | Whether the account still has to set its date of birth |
| authenticator_types | array[integer] | Second-factor [authenticator types](/http-api/users/#authenticator-types) (at most 10) |
| last_active_at | ?ISO8601 timestamp | When the account was last active |
| last_active_ip<sup>4</sup> | ?string | The IP address the account was last active from |
| last_active_ip_reverse<sup>4</sup> | ?string | The reverse DNS name of that address |
| last_active_location<sup>4</sup> | ?string | The approximate location of that address |

<sup>1</sup> Other Admin objects use a zero-padded string. On an instance with the `none` tag style, every account that is not a bot has `0`

<sup>2</sup> Needs `user:view:email`

<sup>3</sup> Needs `user:view:dob`

<sup>4</sup> Needs `user:view:ip`

## List users

<RouteHeader method="GET" path="/v1/admin/users" auditReason />

Finds accounts by one selector and returns [Admin user](#admin-user-object) objects. You need `user:lookup`. When you send more than one selector, the first one in this order wins: `user_id`, `resolve`, `email`, `last_active_ip`, `acl`, then `q`.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| user_id? | array[snowflake] | Exact account IDs, repeated for more than one (at most 100) |
| resolve?<sup>1</sup> | string | A tag, account ID or email address to match one account (1-1024 characters) |
| email?<sup>2</sup> | string | An exact email address (1-320 characters) |
| last_active_ip?<sup>3</sup> | string | An exact last active IP address (1-64 characters) |
| acl? | string | An [ACL](/admin-api/#acl-registry), to list the accounts that have it |
| q? | string | A search query (1-1024 characters) |
| limit?<sup>4</sup> | integer | How many accounts to return (1-200, default 50) |
| offset?<sup>4</sup> | integer | How many results to skip (0-100000, default 0) |

<sup>1</sup> A value with `@` needs `user:view:email`

<sup>2</sup> Needs `user:view:email`

<sup>3</sup> Needs `user:view:ip`

<sup>4</sup> Only for `last_active_ip`, `acl` and `q`

### Response body

| Field | Type | Description |
| --- | --- | --- |
| users | array[[Admin user](#admin-user-object) object] | The matching accounts |
| total | integer | How many accounts matched |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | response body | The search finished, even with no matches |
| 403 | [error response](/admin-api/#error-response) | `FEATURE_TEMPORARILY_DISABLED` when `q` runs on an instance with no search backend |

The rate limit is 200 requests per minute, on the `admin:lookup` bucket.

## Create user

<RouteHeader method="POST" path="/v1/admin/users" auditReason />

Creates an account with no password and returns a [password reset link](#password-reset-link-object) the account holder opens to choose one. You need `*`.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| username | string | The username (1-32 characters) |
| email?<sup>1</sup> | string | The email address |
| admin? | boolean | Whether to give the account `*` (default false) |

<sup>1</sup> Required on an email instance and refused with `USERNAME_SIGN_IN_ONLY` on a username instance

### Response body

| Field | Type | Description |
| --- | --- | --- |
| user | [Admin user](#admin-user-object) object | The new account |
| password_reset | [password reset link](#password-reset-link-object) object | The link the account holder opens to choose a password |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | response body | The account was created |
| 400 | [error response](/admin-api/#error-response) | The username or email address is taken or invalid |

The rate limit is 100 requests per minute, on the `admin:user:modify` bucket.

## Resend verification email

<RouteHeader method="POST" path="/v1/admin/users/{user_id}/verification-email" auditReason />

Emails the account holder a new verification link. You need `user:update:email`. Nothing is sent when the address is already verified, has bounced or the instance doesn't send email.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The request was accepted |
| 400 | [error response](/admin-api/#error-response) | `INVALID_FORM_BODY` with `USER_DOES_NOT_HAVE_AN_EMAIL_ADDRESS` when the account has no address |
| 403 | [error response](/admin-api/#error-response) | `BOT_USER_AUTH_ENDPOINT_ACCESS_DENIED` when the account is a bot |
| 429 | [error response](/admin-api/#error-response) | The address already got three verification emails in 15 minutes |

## Delete all user messages

<RouteHeader method="DELETE" path="/v1/admin/users/{user_id}/messages" auditReason />

<sup>1</sup> Required unless it is a dry run

### Response body

| Field | Type | Description |
| --- | --- | --- |
| success | boolean | Always true |
| dry_run | boolean | Whether the request only counted |
| channel_count | integer | About how many channels have the account's messages |
