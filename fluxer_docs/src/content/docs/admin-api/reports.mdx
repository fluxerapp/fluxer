A report is one complaint against a message, an account or a guild, with the evidence Fluxer captured when it was filed. Use these routes to review reports, resolve them and delete them. People file reports through the public [Reports](/http-api/reports/) resource, which defines the [categories](/http-api/reports/#report-categories) and [reasons](/http-api/reports/#report-reasons).

## Admin report object

[List reports](#list-reports) returns this object. [Get report](#get-report) returns the [Admin report detail object](#admin-report-detail-object), which extends it with message context. The guild, channel, webhook and message fields are copied when the report is filed. The account names are looked up when Fluxer builds the response. `reporter_email`, `reporter_full_legal_name` and `reporter_country_of_residence` are null unless you have `report:view:reporter_pii` as well as `report:view`.

## Report status

| Value | Name | Description |
| --- | --- | --- |

| 1 | RESOLVED | The report was reviewed and resolved |

| 2 | GUILD | A guild was reported |

## Report retention

A pending report is kept until it is resolved. A resolved report is deleted with its notes and evidence copies 365 days after `resolved_at`, and you can change the number of days with `FLUXER_REPORT_RETENTION_DAYS` on `worker`, which runs retention once a day. Three kinds of report are kept longer.

- A `child_safety` report is kept at least 365 days after it was resolved, even when `FLUXER_REPORT_RETENTION_DAYS` is lower.
- A report linked from an [enforcement decision](/admin-api/enforcement/#enforcement-decision-object) is kept at least 365 days after the newest such decision.
- A report with a [legal hold](#set-report-legal-hold) is kept until the hold ends.

Every report, pending or resolved, loses its message context, profile snapshot, additional info and evidence copies 365 days after it was filed, unless it has a legal hold. The record and its notes stay.

When a report is resolved as `no_violation` and isn't one of the reports above, its message context, profile snapshot, additional info and evidence copies are deleted 184 days after it was resolved, and the rest of the record is deleted when the retention period ends.

:::caution[Deleted evidence can't be restored]
To see what retention would delete before it deletes anything, set `FLUXER_REPORT_RETENTION_DRY_RUN` to `true` on `worker`. It then logs each report it would delete and deletes nothing.
:::

## List reports

<RouteHeader method="GET" path="/v1/admin/reports" auditReason />

Returns a page of [Admin report](#admin-report-object) objects. You need `report:view`.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| q?<sup>1</sup> | string | Free-text query (1-1024 characters) |
| status? | pending \| resolved | Filter by [report status](#report-status) |
| report_type? | message \| user \| guild | Filter by [report type](#report-type) |
| category? | string | Filter by category (1-128 characters) |
| reason? | string | Filter by [report reason](/http-api/reports/#report-reasons) key (1-64 characters) |
| reporter_id? | snowflake | Filter by reporter |
| reported_user_id? | snowflake | Filter by reported account |
| reported_webhook_id? | snowflake | Filter by the [webhook](/http-api/webhooks/) that sent the reported message |
| reported_guild_id? | snowflake | Filter by reported guild |
| reported_channel_id? | snowflake | Filter by reported channel |
| guild_context_id? | snowflake | Filter by the guild the report was filed from |
| resolved_by_admin_id? | snowflake | Filter by the admin who resolved the report |
| sort_by?<sup>2</sup> | created_at \| reported_at \| resolved_at | Sort field (default `reported_at`) |
| sort_order?<sup>2</sup> | asc \| desc | Sort direction (default `desc`) |
| limit? | integer | Maximum reports to return (1-200, default 50) |
| offset? | integer | Reports to skip (0-10000, default 0) |

<sup>1</sup> Matches `category`, `additional_info`, `reported_guild_name` and `reported_channel_name`

<sup>2</sup> Ignored when `status` is the only filter, and those results are always newest first by `reported_at`

### Response body

| Field | Type | Description |
| --- | --- | --- |
| reports | array[[Admin report](#admin-report-object) object] | The reports in this page |
| total | integer | The number of matching reports |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | response body | The page was returned |
| 403 | [error response](/admin-api/#error-response) | `FEATURE_TEMPORARILY_DISABLED` when the instance has no search backend |

## Update report

<RouteHeader method="PATCH" path="/v1/admin/reports/{report_id}" auditReason />

Resolves a pending report and returns a [report resolution](#report-resolution-object) object. You need `report:resolve`.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| status | resolved | The new status |
| public_comment? | string | The comment shown to the reporter (0-512 characters) |
| notify_reporter?<sup>1</sup> | boolean | Whether the notice to the reporter includes `public_comment` (default true) |
| resolution | string | `actioned`, `no_violation` or `duplicate` |
| outcome? | string | `removed`, `warned`, `restricted`, `action_taken` or `no_violation` |
| duplicate_of? | snowflake | The report this one repeats |

<sup>1</sup> The reporter gets a notice either way. False leaves the comment out of the notice and off the report, and Fluxer keeps it only in the audit entry as `internal_comment`

The `resolution` decides which of the other fields you send.

| resolution | outcome | duplicate_of |
| --- | --- | --- |
| actioned | Required, any value except `no_violation` | Not allowed |
| no_violation | Optional, only `no_violation` | Not allowed |
| duplicate | Not allowed, copied from the `duplicate_of` report | Required, and not this report |

The `outcome` is one of these values.

| Outcome | Description |
| --- | --- |
| removed | The reported content, profile field or guild was removed |
| warned | The account responsible was warned, and the reporter is told action was taken |
| restricted | The reported account was restricted |
| action_taken | Fluxer acted another way and doesn't tell the reporter how |
| no_violation | The reported content breaks no rule |

[Schedule user deletion](/admin-api/users/#schedule-user-deletion) with [deletion reason](/admin-api/users/#deletion-reasons) 3, 4, 5, 6, 8, 11, 17, 18, 20, 21 or 22 also resolves the pending reports against that account with the outcome `restricted` and no comment, except reports in the `child_safety`, `underage_user` and `self_harm` categories. An [enforcement decision](/admin-api/enforcement/) resolves the pending reports it links.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [report resolution](#report-resolution-object) object | The report was resolved |
| 400 | [error response](/admin-api/#error-response) | `REPORT_ALREADY_RESOLVED` when the report is already resolved |
| 400 | [error response](/admin-api/#error-response) | `INVALID_FORM_BODY` with `REPORT_OUTCOME_INVALID` when `outcome` or `duplicate_of` doesn't fit `resolution` |
| 404 | [error response](/admin-api/#error-response) | `UNKNOWN_REPORT` when the report or the `duplicate_of` report doesn't exist |

### Side effects

The reporter gets a system DM with the outcome, which sends [Channel Create](/gateway/events/#channel-create) and [Message Create](/gateway/events/#message-create), and an email when the account has an email address. A Digital Services Act notice and an instance with direct messages turned off get the email only. Fluxer sends nothing when the reporter's account is deleted, when it was barred from reporting at the time of the report, or when the report is a duplicate of one with no outcome yet.

The rate limit is 200 requests per minute, on the `admin:lookup` bucket.

## Add a note to a report

<RouteHeader method="POST" path="/v1/admin/reports/{report_id}/notes" auditReason />

Adds a [note](#report-note-object) to a report, pending or resolved, and returns it. You need `report:resolve`.

### JSON body

| Field | Type | Description |

| body | string | The note (1-2000 characters) |

### Response

| Status | Body | Condition |

## Set report legal hold

<RouteHeader method="POST" path="/v1/admin/reports/{report_id}/legal-hold" auditReason />

Places or clears a legal hold and returns a [report legal hold](#report-legal-hold-object) object. You need `report:resolve`. [Retention](#report-retention) doesn't delete a held report until the hold ends, and a new hold replaces the old one.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| legal_hold_until | ?ISO8601 timestamp | When the hold ends (in the future), or null to clear the hold |
| legal_hold_reason? | ?string | Why the report is held (1-512 characters), required to place a hold |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [report legal hold](#report-legal-hold-object) object | The hold was placed or cleared |
| 400 | [error response](/admin-api/#error-response) | `INVALID_FORM_BODY` when `legal_hold_until` isn't in the future or a hold has no reason |
| 404 | [error response](/admin-api/#error-response) | `UNKNOWN_REPORT` when the report doesn't exist |

The rate limit is 200 requests per minute, on the `admin:lookup` bucket.

## Delete report

<RouteHeader method="DELETE" path="/v1/admin/reports/{report_id}" auditReason />

Deletes a report with its notes and evidence copies right away, without telling the reporter. You need `report:delete`.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The report was deleted |
| 404 | [error response](/admin-api/#error-response) | `UNKNOWN_REPORT` when the report doesn't exist |
| 409 | [error response](/admin-api/#error-response) | `REPORT_UNDER_LEGAL_HOLD` when the report has a legal hold that hasn't ended |

The rate limit is 200 requests per minute, on the `admin:lookup` bucket.
