Instance configuration is everything an instance admin can change at runtime, from sign-in and registration to branding, integrations, billing and limits. The [Instance](/http-api/instance/) resource publishes part of it to clients.

No read returns a stored secret, and a boolean such as `client_secret_set` says whether one is set.

## Instance configuration object

The full runtime configuration. A setting that was never saved uses the default in its table.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| sso | [SSO configuration](#sso-configuration-object) object | Single sign-on settings |
| gateway_rollout | [Gateway rollout configuration](#gateway-rollout-configuration-object) object | Gateway admission and dispatch tuning |
| push_relay | [push relay configuration](#push-relay-configuration-object) object | Consent to the Fluxer-run push relay |

## Account identity configuration object

How people sign in. It is read-only here, and the setup wizard sets it through [set the setup sign-in method](/http-api/instance/#set-the-setup-sign-in-method). [Sign-in methods](/operator/sign-in/) explains the rules.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| mode | string | The [account identity mode](/http-api/instance/#account-identity-modes), `email` or `username` |
| locked | boolean | Whether the mode is fixed, with the reason in `lock_reason` |
| tag_style | string | One of the [tag styles](/http-api/instance/#tag-styles) |
| lock_reason | ?string | One of the [account identity lock reasons](/http-api/instance/#account-identity-lock-reasons), or null |

## Peer-to-peer voice configuration object

The rollout that lets small calls connect people directly, without the voice servers. [Experiments](/http-api/experiments/#peer-to-peer-voice-assignment-object) describes what a client gets from it.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| enabled | boolean | Whether the rollout runs at all (default false) |
| config_version | integer | Revision counter that Fluxer raises on each change |
| rollout_basis_points | integer | Share of accounts selected, in basis points (0-10000, default 0) |
| rollout_country_codes | array[string] | ISO 3166-1 alpha-2 codes that limit the sampled share (up to 250 entries, default empty) |
| rollout_salt | string | Salt of the sampling hash (1-64 printable ASCII characters, default `voice-p2p-v1`) |
| included_user_ids | array[snowflake] | Accounts always selected (up to 1000 entries, default empty) |
| included_guild_ids | array[snowflake] | Guilds whose members are always selected (up to 1000 entries, default empty) |
| include_premium_users | boolean | Whether accounts with active premium are always selected (default false) |
| excluded_user_ids | array[snowflake] | Accounts never selected, which wins over every other rule (up to 1000 entries, default empty) |
| max_participants | integer | Most people in one peer-to-peer call (2-4, default 2) |

Selection decides who can start a peer-to-peer call, and anyone can join one while `enabled` is true. Setting `enabled` to false makes new calls use the voice servers, and a running peer-to-peer call keeps going until it ends.

### Structure

| --- | --- | --- |

## Accounts configuration object

What accounts have to do before they can interact with other people, and which accounts Fluxer deletes.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| date_of_birth<sup>1</sup> | string | `off`, `ask`, `require_new_accounts` or `require_all` |
| interaction_tier<sup>2</sup> | string | `legacy` or `enforced` |
| verification_basis<sup>3</sup> | string | `auto`, `confirmed_email` or `local_credential` (default `auto`) |
| guild_join_gate<sup>4</sup> | string | `off`, `visits_capable` or `always` (default `always`) |
| unclaimed_account_cleanup<sup>5</sup> | [unclaimed account cleanup](#unclaimed-account-cleanup-object) object | Deleting accounts nobody can sign in to again |
| dob_missing_cleanup | [date of birth cleanup](#date-of-birth-cleanup-object) object | Deleting accounts created without a date of birth, while `date_of_birth` isn't `off` |
| inactivity_deletion<sup>6</sup> | [inactivity deletion](#inactivity-deletion-object) object | Deleting accounts nobody has used for a long time |

<sup>1</sup> `ask` asks accounts without one and refuses nothing. `require_new_accounts` refuses most operations to new accounts until they [set one](/http-api/users/current-user/#set-date-of-birth), and `require_all` does the same for every account without one

<sup>2</sup> How the [account tiers](/http-api/users/#account-tiers) apply. `enforced` lets an account that hasn't finished setting up do only things that don't involve other people

<sup>3</sup> `confirmed_email` needs a confirmed email and `local_credential` needs a password or a passkey. `auto` uses `confirmed_email` while the instance sends email, and a `username` instance always uses `local_credential`

<sup>4</sup> Whether joining a community needs a verified account. It applies to people assigned [guild visits](#guild-visits-configuration-object) while `interaction_tier` is `enforced`, and `visits_capable` checks only clients that send `X-Fluxer-Capabilities: guild_visits`

<sup>5</sup> Bot, system and single sign-on accounts are never deleted this way. `on_last_session_end` set to `after_grace` also schedules the deletion when the account signs out of its last session. Each deletion is scheduled 24 hours ahead, and signing in cancels it

<sup>6</sup> Fluxer emails a warning first and deletes the account `warning_lead_days` later unless it is used. An account that never got the warning, such as one with no email, is never deleted this way

#### Unclaimed account cleanup object

| Field | Type | Description |
| --- | --- | --- |
| mode | string | `off` or `after_inactivity` |
| inactive_days | integer | Days without use before the account is deleted (1-3650) |
| on_last_session_end | string | `off` or `after_grace` |

#### Date of birth cleanup object

| Field | Type | Description |
| --- | --- | --- |
| mode | string | `off` or `after_inactivity` |
| inactive_days | integer | Days without use before the account is deleted (1-3650) |

#### Inactivity deletion object

| Field | Type | Description |
| --- | --- | --- |
| mode | string | `off` or `after_inactivity` (default `after_inactivity`) |
| inactive_days | integer | Days without use before the warning email is sent (1-3650, default 730) |
| warning_lead_days | integer | Days between the warning email and the deletion (1-365, default 30) |

A new self-hosted instance starts with `date_of_birth` set to `off` and `interaction_tier` set to `enforced`. It deletes unclaimed accounts after 90 days with `after_grace`, and accounts without a date of birth after 7 days. An upgraded instance starts in `legacy` with both cleanup policies off. Every instance starts with inactivity deletion on.

| Value | Description |

### Billing emails

When `billing_emails` is on, turn off the matching Stripe customer emails, or buyers get two of each:

- Settings > Business > Customer emails > Payments: **Successful payments** and **Refunds**
- Revenue recovery > Emails: **Send emails when card payments fail** and **Send a Stripe-hosted link for customers to confirm their payments when required**, and with it **Send reminders if payment confirmation isn't completed**
- Settings > Billing > Subscriptions and emails > Manage invoices sent to customers: **Send credit notes to customers**

Keep **Send emails about upcoming renewals** and **Send emails about expiring cards** on. Gifts redeemed on a paying subscription are Stripe trials, so also turn off **Send a reminder email 7 days before a free trial ends**.

The webhook endpoint at `webhook_url` must receive these events for the emails: `invoice.paid`, `invoice.payment_succeeded`, `invoice.payment_failed`, `invoice.payment_action_required`, `refund.created`, `refund.updated` and `charge.refunded`. Billing itself also needs the `checkout.session.*`, `customer.subscription.*`, `invoice.*`, `charge.dispute.*` and `refund.failed` events.

## Update instance configuration

<RouteHeader method="PATCH" path="/v1/admin/instance/config" auditReason />

Merges the body into the saved configuration and returns the [instance configuration](#instance-configuration-object). You need `instance:config:update`. Sections and keys you leave out keep their saved value, and null clears a nullable key.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| sso?<sup>1</sup> | object | [SSO configuration](#sso-configuration-object) fields except `client_secret_set` and `redirect_uri`, plus `client_secret` |
| gateway_rollout? | object | Any [Gateway rollout configuration](#gateway-rollout-configuration-object) fields |
| push_relay? | object | `relay_consent_accepted` from the [push relay configuration](#push-relay-configuration-object) |
| voice_p2p? | object | Any [peer-to-peer voice](#peer-to-peer-voice-configuration-object) fields |
| captcha? | object | Any [captcha configuration](#captcha-configuration-object) fields |
| experiment_delivery? | object | Any [experiment delivery](#experiment-delivery-configuration-object) fields |
| registration? | object | `mode`, `admin_registration_urls_enabled` and `allowed_email_domains` |
| app_public?<sup>2</sup> | object | `branding`, `setup`, `legal` and `registration` objects, each merged field by field |
| integrations?<sup>3</sup> | object | `gif`, `youtube`, `email` and `bluesky` objects, and `bluesky.keys` |
| media? | object | `attachment_decay` overrides, null to restore a default |
| policy? | [instance policy update](#instance-policy-update-structure) object | Community, direct message, premium and gating policy |
| billing?<sup>4</sup> | object | [Instance billing](#instance-billing-object) fields, plus `stripe_secret_key` and `stripe_webhook_secret` |
| auth? | object | `identifier_first` and any `instant_accounts` fields from the [auth configuration](#auth-configuration-object) |
| accounts? | object | Any [accounts configuration](#accounts-configuration-object) fields |
| guild_visits? | object | Any [guild visits configuration](#guild-visits-configuration-object) fields |
| notice?<sup>5</sup> | object | `message`, `url`, `starts_at` and `ends_at` of the [instance notice](/http-api/instance/#instance-notice-object) |

<sup>1</sup> While `enabled` is true, endpoint URLs must use `https` and point at a public address unless `FLUXER_SSO_ALLOW_PRIVATE_ADDRESSES` is true. Turning on both `enabled` and `enforced` fails with `SSO_MISCONFIGURED` unless there is an `issuer`, or an authorization endpoint, a token endpoint, a client ID and `jwks_url` or `userinfo_url`

<sup>2</sup> `branding.product_name` is 1-80 characters, `branding.premium_product_name` 1-40, `branding.custom_css` up to 32,768 and `branding.upload_limit_message` up to 500. `branding.trusted_domains` holds up to 50 hostnames, each optionally starting with `*.`, and null clears it. URLs are up to 2048 characters and `branding.theme_color` is a hex color. Setting `setup.configured` to true finishes setup, and accounts that register after that don't get the wildcard Admin ACL

<sup>3</sup> A secret such as `klipy_api_key`, `api_key` or the SMTP `password` is saved when sent and kept when left out. `email.smtp` takes `host`, `port`, `username`, `password` and `tls_mode`. `bluesky.keys` replaces the signing keys with up to 8 entries of `kid` and `private_key`

<sup>4</sup> `prices`, `country_currencies` and `legacy_prices` replace the saved value, and an empty `prices` object goes back to the environment prices. Billing can't be on while the premium mode is `everyone`

<sup>5</sup> `message` is up to 1000 characters, and null or an empty string removes the notice. A request replaces the whole notice

Fluxer checks the merged settings before it writes anything, and refuses these combinations with 400 `INVALID_FORM_BODY`.

- `INSTANT_ACCOUNTS_REQUIRE_CAPTCHA` when instant accounts are turned on while the captcha provider is `none`
- `CAPTCHA_REQUIRED_BY_INSTANT_ACCOUNTS` when the captcha provider is set to `none` while instant accounts are on
- `IDENTIFIER_FIRST_REQUIRES_EMAIL_IDENTITY` when `identifier_first` is set to `on` on a `username` instance
- `EMAIL_DELIVERY_REQUIRES_EMAIL_IDENTITY` when email delivery is set to `smtp` on a `username` instance
- `SMTP_HOST_REQUIRED` when email delivery is set to `smtp` with no SMTP host saved or in the environment
- `VERIFICATION_BASIS_REQUIRES_EMAIL_DELIVERY` when `verification_basis` is `confirmed_email` while the instance doesn't send email

It also refuses `sso.username_from_provider` set to true on an instance that isn't a `username` instance.

#### Instance policy update structure

| Field | Type | Description |
| --- | --- | --- |
| single_community_enabled?<sup>1</sup> | boolean | Whether the instance presents one community |

<sup>2</sup> True starts a background job that adds every account that can sign in, except bots and accounts waiting for approval. Sending it again restarts the job
