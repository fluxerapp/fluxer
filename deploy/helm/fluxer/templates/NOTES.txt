{{- if $v.maintenance }}
Fluxer is in maintenance and does not start. Restore a backup into it
  kubectl -n {{ .Release.Namespace }} exec -i {{ $fullname }}-0 -- fluxerd restore - < fluxer-backup.tar.zst

Then set maintenance to false with helm upgrade, and Fluxer starts with the restored data.
{{- else if .Release.IsUpgrade }}
Fluxer is starting {{ include "fluxer.image" . }} at https://{{ include "fluxer.host" . }}. When it's newer than the release before, it backs up the database first, then upgrades it.

Watch it become ready
  kubectl -n {{ .Release.Namespace }} rollout status statefulset/{{ $fullname }} --timeout 15m

If it doesn't become ready, its log says why
  kubectl -n {{ .Release.Namespace }} logs {{ $fullname }}-0
{{- else }}
Fluxer is starting at https://{{ include "fluxer.host" . }}. On a new claim the first start creates the database and takes a few minutes.

Watch it become ready
  kubectl -n {{ .Release.Namespace }} rollout status statefulset/{{ $fullname }} --timeout 15m

If this is a new instance, create the first admin account with the setup token, then open https://{{ include "fluxer.host" . }}
  kubectl -n {{ .Release.Namespace }} exec {{ $fullname }}-0 -- fluxerd setup-token

{{- if include "fluxer.ipDomain" . }}

The Service {{ $fullname }} asks for the address {{ $v.edge.loadBalancer.loadBalancerIP | default (include "fluxer.bareIP" .) }}. On a public address Fluxer gets a Let's Encrypt certificate once ports 80 and 443 on it are open to the internet. On a private address Fluxer signs its own certificate, and each device that opens it has to trust that certificate, from http://{{ include "fluxer.host" . }}/fluxer-root.crt. That link uses plain HTTP, so before you trust the file, check that its SHA-256 fingerprint matches the one this command prints.
  kubectl -n {{ .Release.Namespace }} exec {{ $fullname }}-0 -- cat /var/lib/fluxer/edge/caddy/pki/authorities/local/root.crt | openssl x509 -noout -fingerprint -sha256
{{- else }}

Point {{ $v.domain }} at the address of the Service {{ $fullname }}. Fluxer gets its certificate once ports 80 and 443 answer on that name.
{{- end }}
  kubectl -n {{ .Release.Namespace }} get service {{ $fullname }}

{{- if eq $v.voice.expose "hostPort" }}

Voice uses TCP 7881 and UDP 7882 on the node that runs the pod. The pod stays Pending on a node where something else holds those ports, such as another Fluxer release or the LiveKit of a 0.x release. A namespace that enforces Pod Security baseline or restricted refuses host ports, and the pod never starts there. Set voice.expose to loadBalancer or nodePort in either case.

Back up
  kubectl -n {{ .Release.Namespace }} exec {{ $fullname }}-0 -- fluxerd backup --out - > fluxer-backup.tar.zst

Upgrade, with Helm 3.14 or later, Helm 4 included, and the new release in place of <version>. With config.FLUXER_UPDATE_CHECK set to "true", the Updates page of the admin panel shows this command with the version filled in when a newer release is out
  {{ include "fluxer.upgradeCommand" . | replace "{version}" "<version>" }}

Fluxer backs up its database before every upgrade. After a helm rollback to an older release it stays up but not ready and logs the restore command to run with kubectl exec.

A 0.x release can't be upgraded to this chart. Install this chart under a new release name and move the data with fluxerd import, as in https://docs.fluxer.com/operator/moving/#moving-from-the-0x-chart
